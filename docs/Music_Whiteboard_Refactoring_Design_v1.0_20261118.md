## 1. 목표와 기준선

교사가 장면을 만들어 한 번에 저장하고, 수업에서는 상단 헤더에서 판서를 한 단계씩 진행한다. 기존 장면 편집·초안·충돌 감지·휴지통·JSON 백업을 보존하면서 손글씨 적용 범위를 넓힌다. 이어서 판서 소리, 조표와 여러 화음, 이론 검증, 수업 묶음과 건반 활동을 현재 앱에 추가하는 순서로 설계한다.

애니메이션 데이터가 표시 내용의 원본이 되지 않도록 한다. 저장한 장면과 순서가 원본이고 렌더 계획, 치수, 음향 스케줄과 화면 읽기용 설명은 여기에서 만든다. 내용을 바꾸지 않은 크기·테마 변경은 장면 revision을 올리지 않는다. 미리보기는 편집 스냅샷을 재생하며 현재 장면이나 수업 순서를 바꾸지 않는다. 장면 저장본, 미완성 초안, 장치별 보기 설정, 수업 진행 위치를 서로 다른 수명으로 관리한다.

## 4. 1단계 · 편집과 기본 조작 안정화

이 단계에서 교사는 입력 직후 한 번 눌러 저장하고, 메뉴를 닫은 직후 발표용 리모컨으로 수업을 이어갈 수 있다. 장면의 JSON 형식과 IndexedDB 저장 구조는 기존 계약을 사용한다.

### 4.1 편집 화면의 DOM 수명 분리 (A1, A6, D5)

**변경 지점**은 `src/scene-editor.js`의 `render`, `rerender`, `input`·`change` 핸들러와 `src/app.js`의 `editDoc`이다. 기존 `render()`가 `dialog.innerHTML`을 교체하는 구조에서 질문과 본문이 포커스를 잃는 순간 다음 클릭의 대상도 사라진다.

1. 대화창을 열 때 제목, 탭, 본문 컨테이너, 오류 요약, 내용 확인, 하단 버튼의 뼈대를 한 번 생성한다. 제목·질문·정리 문장·본문·화음 이름·단계 이름은 `input`으로 초안에 반영한다. `change`로 포커스가 이동할 때 요청되는 전체 렌더를 제거한다.
2. 텍스트 입력 시 바뀐 초안 값, 내용 확인의 해당 줄, 글꼴 지원 안내, 해당 필드의 오류 상태와 글자 수만 갱신한다. 입력 값과 커서 위치를 가진 노드 및 저장·본문 추가 버튼은 같은 DOM 노드를 유지한다. 사용자 텍스트는 `textContent` 또는 기존 이스케이프 경로로 표시한다.
3. 템플릿 전환은 템플릿 필드와 단계 영역, 음·본문 추가 및 삭제는 해당 목록과 연관 단계만 바꾼다. 선택값이 다른 필드의 표시를 바꿀 때 해당 필드만 갱신한다. 예를 들어 화음 음을 변경하면 프리셋이 직접 입력으로 전환되고 로마 숫자 안내와 판서 그룹 라벨을 갱신한다. 그룹 키와 단계 ID는 기존 값을 그대로 사용한다.
4. 부분 교체가 필요한 컨트롤은 `필드 경로 + 레코드 ID`로 포커스 대상을 식별한다. 추가 후 새 항목의 첫 입력, 삭제 후 같은 위치의 다음 항목 또는 직전 항목, 항목이 없을 때 추가 버튼, 순서 이동 후 이동한 항목의 같은 조작 버튼으로 포커스를 보낸다. 버튼이 비활성화된 경우 해당 항목의 입력이나 제목으로 이동한다. 컨테이너 스크롤을 유지하고 이동 대상이 가려진 경우에만 보이도록 스크롤한다. 템플릿 변경을 취소하면 이전 값과 포커스를 유지한다.
5. 한국어 조합 중에는 입력 노드를 교체하지 않고 내용 확인과 필드 검증 갱신을 유예한다. `compositionend`에서 확정된 값을 반영한다. 저장·미리보기 요청의 시작 지점에서 조합이 끝난 마지막 입력을 반영한 뒤 `validateScene`과 배치 검사를 호출한다. 조합 Enter는 저장 단축키로 처리하지 않는다.
6. 저장은 기존 800ms 초안 자동 저장과 큐를 이어받는다. 성공 경로는 예약된 타이머 취소 → 실행 중인 초안 쓰기 완료 → 원본 `revision` 확인과 저장 → 대화창 닫기 → 성공 알림 순으로 실행한다. 요청이 진행 중일 때 저장을 중복 호출할 수 없게 한다. 실패·충돌 시 입력과 최신 초안, 초안 파일 내보내기 경로를 보존한다. 오류 후 저장 버튼 상태를 복구하되 화면 전체를 다시 그리지 않는다.
7. 내용 확인과 판서 순서에 교사에게 익숙한 이름을 쓴다. 음 옵션의 값은 `C4` 등을 그대로 사용하고 레이블은 `도 (C4)` 형식으로 표시한다. `note/<id>` 등은 현재 배열에서 참조를 찾아 `음표 1 (도)`, `계이름 1 (도)`, `본문 2`로 표시한다. 가져온 레코드에서 참조를 찾을 수 없으면 모델 검증 오류로 표시한다. UUID를 안내 문구에 노출하지 않는다.
8. 오류는 `질문 · 내용을 입력해 주세요`처럼 필드 이름과 메시지를 함께 표시한다. 첫 오류가 있는 모바일 탭을 열고 해당 필드를 포커스하며, `aria-invalid`와 `aria-describedby`를 연결한다. 입력이 정상으로 돌아오면 오류 연결과 메시지를 제거한다. 휴대폰 하단에는 `미리보기`와 `장면 저장`을 우선 배치하고 초안 내보내기와 닫기는 대화창 헤더의 추가 작업으로 이동한다. 320px 폭에서도 저장 버튼이 본문 입력을 가리지 않도록 확인한다.
9. 실제 판면을 확인하는 기본 경로는 기존 전체 화면 미리보기다. 내용 확인 탭에서 바로 실행할 수 있도록 배치한다. 썸네일이 필요하면 이후 단계에서 `buildDocumentScene`으로 만든 완료 판면을 기존 렌더러로 정적으로 그린다. 동일한 페이지에 여러 SVG가 생길 경우 마스크·패턴 ID를 렌더러마다 고유하게 하고, 이전 미리보기 렌더러를 해제한다.

### 4.2 단축키, 목록 포커스, 알림 (A3, A4, A7)

**변경 지점**은 `src/app.js`의 전역 `keydown`과 `openList`, `src/ui/scene-list.js`의 대화창 종료 처리, `src/index.html`과 `src/style.css`다.

| 입력과 위치 | 실행 규칙 |
| --- | --- |
| 수업 화면의 ←, →, Page Up, Page Down | 이전·다음 단계. 닫힌 메뉴의 제목이나 평상시 헤더 버튼에 포커스가 있어도 작동한다. |
| 수업 화면의 Shift+Page Up·Down | 이전·다음 장면. 현재 장면 순서와 미리보기 여부를 확인하고 호출한다. 경계에서는 장면을 이동하지 않는다. |
| 수업 화면의 Space | 칠판 진행에 사용한다. 포커스가 버튼, 링크, 메뉴 제목에 있으면 해당 요소의 기본 키보드 동작을 따른다. |
| 검색·편집 입력, 셀렉트, 편집 가능한 텍스트, 열린 메뉴·대화창 | 입력과 해당 컨트롤의 키보드 조작을 우선한다. 목록 검색창의 Enter와 아래 화살표도 기존 흐름을 유지한다. |
| IME 조합, 키 반복, Ctrl·Meta·Alt 조합 | 전역 판서 동작을 시작하지 않는다. 처리하는 단축키에만 `preventDefault()`를 호출한다. |

- 일반 메뉴를 Esc로 닫으면 해당 메뉴 제목으로 초점을 돌린다. 이곳에서도 방향키와 Page Up·Down은 이미 작동한다. 장면 목록에서 선택 완료 후 닫히면 수업 화면의 현재 장면 표시나 다음 단계로 포커스를 옮긴다. 취소한 경우에는 기존 진입점을 복원한다. 진입점이 닫힌 메뉴 안의 버튼이면 해당 메뉴 제목을 후속 후보로 사용한다. 메뉴 안의 실제 명령을 실행하면 메뉴를 닫으며, 설정 메뉴의 셀렉트 조작은 선택 후에도 추가 설정을 할 수 있게 둔다.
- `도움말`의 접힌 영역에서 피드백을 꺼내 헤더에서 항상 접근 가능한 상태 영역을 만든다. 정보·성공 알림은 `role="status"`로 안내하고 약 5초 후 시각 표시를 지운다. 중대 오류는 별도 `role="alert"`로 전달하고 해결하거나 닫을 때까지 유지한다. 장면의 단계 진행은 헤더의 단계 표시만 갱신해 같은 내용을 두 영역에서 읽지 않게 한다. 사용자가 알림을 읽는 도중 새 일반 알림이 중대 오류를 덮지 않도록 분리한다.
- 열린 모달 안의 저장 오류는 그 모달의 피드백 영역에서 안내한다. 저장 성공은 대화창이 닫혀 헤더가 다시 접근 가능해진 뒤 알린다. 내보내기는 브라우저 다운로드 요청을 시작했음을 표시하며, 파일이 실제 기기에 저장됐는지는 브라우저가 표시한다.
- 검색이 헤더에 남아 있는 동안 `.header-search button`을 줄바꿈 없이 유지하고 버튼 폭을 내용과 여백에 맞게 보호한다. 입력은 가용 폭에 따라 줄일 수 있다. 2단계에서는 검색 폼을 장면 메뉴 안으로 이동한다.

## 5. 2단계 · 수업 화면과 재생 안정화

### 5.1 헤더 중심의 수업 화면 (A2, C2)

기존 제품 요구에 따라 수업 본문에는 칠판을 크게 표시한다. 자주 쓰는 이전·다음·재생을 헤더의 직접 실행 버튼으로 노출하고 나머지 조작은 헤더 메뉴에 둔다. 분석 목록의 하단 터치 조작 줄은 전자칠판에서 상단 접근이 어려울 때 검토할 별도 선택지로 기록한다. 하단 줄을 기본 화면에 도입하려면 사용자의 배치 결정이 필요하다.

| 위치 | 기본 구성 |
| --- | --- |
| 일반 화면 헤더 | 현재 장면 이름과 진행 표시, 이전 단계·시작/재생/일시정지·다음 단계, 장면·판서·보기·도움말 메뉴. |
| 좁은 화면 헤더 | `장면`, 이전, 시작/일시정지, 다음, `도구`를 한 줄에 둔다. `도구` 안에서 판서·보기·도움말로 접근한다. 버튼에는 최소 44×44 CSS px 터치 영역과 정확한 접근 가능 이름을 제공한다. 제목과 긴 단계명은 화면 폭에 맞게 줄이고 읽기 이름에는 원문을 유지한다. 좁은 폭에서 제목과 단계 표시가 다섯 진입점에 함께 들어가지 않으면 제목·진행 표시에만 보조 행을 허용한다. |
| 장면 메뉴 | 현재 장면과 검색, 목록·편집·백업 진입점. 검색 시 기존 목록 대화창을 같은 검색어로 연다. |
| 판서 메뉴 | 이전·다음 장면, 처음부터, 바로 완성, 진행 방식과 모드 설명. |
| 보기 메뉴 | 전체 화면, 테마, 손 모양, 속도, 판서 효과, 선 방식. 보기 설정을 바꿔도 장면에는 쓰지 않는다. |
| 미리보기 | 헤더에 `미리보기 · 저장 전` 표시와 `편집으로 돌아가기`. 단계 진행은 열어 두고 장면 이동 및 장면 목록은 잠근다. |

- 헤더의 이전·다음·재생은 기존 버튼 노드를 새 위치로 이동시켜 단일 실행 경로를 사용한다. 준비 상태에서는 `시작`, 재생 중에는 `일시정지`, 멈춘 상태에서는 `계속`을 표시한다. 최초에 `시작을 눌러 첫 단계를 판서하세요`를 헤더의 진행 안내로 제공한다. 다음 단계 역시 첫 입력으로 시작할 수 있다. 한 번의 터치에는 한 단계 동작만 실행한다. 클릭과 터치 이벤트를 중복으로 바인딩하지 않는다.
- `src/player.js`에서 `innerWidth < 760` 사용을 없애고, `src/app.js`에서 실제 `.board-area`의 content box를 관찰한다. `scene.js`의 두 판면(가로 1000×620, 세로 480×640)에 각각 `scale = min(가용폭 / 판면폭, 가용높이 / 판면높이)`를 적용하고 실제 판면 면적이 큰 쪽을 선택한다. 프레임·안전 여백을 같은 기준으로 먼저 제외한다. 두 결과 차가 5% 이내면 현재 배치를 유지해 경계 부근의 전환을 막는다. 초기 동률은 가로를 선택한다. 크기가 0인 측정값은 다음 유효 측정을 기다린다.
- 헤더 크기, 방향 회전, 전체 화면 변경으로 크기가 달라지면 한 프레임에 한 번만 최신 크기를 처리한다. 측정 대상은 렌더러가 직접 바꾸지 않는 컨테이너로 둔다. 비율과 픽셀 크기가 동일한 재측정은 건너뛴다. 가로·세로 변경 시 양쪽 배치 검사 결과를 반영하고, 오래된 장면이 세로에서 넘치면 가로 판면을 여백에 맞춰 표시하거나 배치 경고를 안내한다. 글자 크기 자동 조정은 손글씨 단계의 배치 기준을 따른다.
- 전체 화면 버튼은 헤더와 칠판을 포함하는 앱 루트에서 실행한다. `fullscreenchange`를 기준으로 버튼 이름과 상태를 갱신하고, 기능이 제공되지 않거나 요청이 거절되면 전체 화면 버튼 상태를 되돌리거나 숨기고 현재 수업을 유지한다. 시스템 전체 화면 종료 키를 가로채지 않는다.

### 5.2 재생 상태와 미리보기 (C5)

`ScenePlayer`의 `ready`, `playing`, `paused`, `waiting`, `completed`를 유지한다. 재생 중에는 획을 그리는 `drawing`과 자동 대기 중인 `holding`을 구분한다.

| 동작 | 상태 전이 |
| --- | --- |
| 시작·다음 | 준비·수동 대기라면 다음 미완료 단계 시작. 획을 쓰는 중이라면 현재 단계만 완성하고 한 번 대기 상태로 전환. 자동 대기 중이라면 대기 시간을 건너뛰고 다음 단계 시작. 이 명령에 따른 한 번의 전이와 저장된 진행 방식은 별도 값으로 다룬다. |
| 이전 단계 | 판서 중인 단계의 부분 획을 취소해 직전 완료 상태를 다시 그린다. 대기 중이거나 전체 완료 상태라면 완료 단계 수를 한 단계 줄여 다시 그린다. 0단계에서는 비활성화한다. |
| 창 크기·보기 설정 변경 | 그리기 중에는 `location()`의 그룹·항목·획 인덱스·문자 위치와 진행률을 캡처한다. 완료 단계만 다시 그린 뒤 `seekLocation()`으로 해당 위치를 복원한다. 자동 대기 중에는 남은 시간을 유지한다. 이전에 실행 중이었던 경우에만 `lastTs`를 초기화하고 재개한다. 일시정지 상태·열린 편집창·숨겨진 탭은 기존 정지 상태를 유지한다. |
| 이전·다음 장면 | 현재 유효한 장면 목록에서 이웃을 확인하고, 첫 항목의 이전 버튼과 마지막 항목의 다음 버튼을 비활성화한다. 검색 결과에서 시작한 순서는 삭제된 장면을 제외한 목록에 한해 사용한다. 저장·가져오기·휴지통 이동·다른 탭 삭제 이후 목록을 새로 계산한다. 현재 장면이 검색 결과에서만 빠졌으면 기본 목록에서 인덱스를 다시 확인한다. 기본 목록에도 없으면 저장된 순서의 위치로 이동하지 않고 첫 기본 장면을 명시적으로 연 뒤 이동 버튼을 다시 계산한다. `index = -1`에서 `index + delta`를 사용하지 않는다. |
| 미리보기 | 장면 이동을 버튼과 키보드 공통 진입점에서 막는다. 돌아갈 때 수업 장면·진행 상태·현재 제목과 편집 탭·포커스를 복구한다. 편집 미리보기의 변경이 최근 연 장면이나 저장된 수업 설정을 교체하지 않게 한다. |

- 장면 변경 요청마다 번호를 발급한다. 조회·레이아웃 준비와 같이 비동기 작업이 끝난 뒤 최신 요청인지를 확인하고, 이전 요청은 헤더나 칠판에 반영하지 않는다. 다음·이전 장면 버튼은 전환 중 임시 비활성화하되 목록에서 교사가 다른 장면을 명시적으로 선택하면 최신 선택을 우선한다. 미리보기에 들어가는 즉시 진행 중인 장면 조회 요청을 무효화한다. `changeScene`은 진입과 조회 완료 양쪽에서 미리보기 상태를 확인한다.
- `openDoc`은 후보 장면의 모델과 레이아웃·재생 계획을 먼저 준비하고 같은 시점에 칠판과 제목·순서를 반영한다. 기존 렌더러를 교체한 뒤 실패했다면 직전 장면 스냅샷에서 칠판·제목·진행 위치를 복원한다. `lastSceneId` 쓰기는 열린 화면과 분리한다. 여러 변경이 연달아 발생하면 최신 값만 쓰도록 저장을 직렬화하고, 실패는 마지막 선택을 기억하지 못했다는 경고로 표시한다.
- 미리보기 준비 실패는 `editDoc`에 전달한다. 장면·진행 위치·장면 순서·제목을 복원하고 임시로 잠근 메뉴와 검색을 해제한 뒤, 편집 대화창의 탭과 미리보기 진입 버튼에 초점을 복구한다. 실패한 미리보기의 문서가 최근 장면으로 저장되지 않도록 한다.
- 단계 전진은 클릭과 키보드를 하나의 명령 함수로 연결하고 처리 중복과 키 반복을 거른다. 상태를 기준으로 각 조작의 실행 가능 여부를 판단한다. 기존 250ms 공용 제한은 없애고 서로 다른 두 번의 의도적인 터치를 수락한다. 장면을 바꾼 직후의 첫 조작도 같은 규칙을 적용한다.
- `next()`와 `previous()`에서 `this.mode = 'step'`을 직접 바꾸는 처리를 제거한다. 수업용 진행 방식을 바꾸는 진입점은 `playMode` 선택과 사용자가 적용한 백업 설정으로 한정한다.
- resize와 설정 변경에서 재생 프레임을 취소한 뒤 세대 번호를 사용해 이전 프레임을 폐기한다. 재구성 초기의 실행 의도와 장면을 기록하고 완료 시 최신 요청인지, 같은 장면인지, 탭이 보이는지, 그사이 교사가 정지하거나 다른 조작을 했는지 확인한다. 조건을 충족한 경우에만 프레임 루프를 하나 예약한다. 부분 획 복원에서 정확한 항목을 찾지 못하면 같은 그룹을 찾고, 그룹도 없으면 해당 단계의 시작점을 사용한다. 이후 음향 단계에서는 다시 그리는 과정의 오디오 이벤트를 억제한다.
- 진행 텍스트는 `2 / 5단계 · 구성음 쓰기`처럼 완료 수와 현재 또는 직전에 완료한 단계 이름을 조합한다. 준비 상태에서는 첫 단계 이름을 제공하고, 자동 대기와 일시정지를 구분한다. 사용자 단계명은 텍스트로만 삽입한다.
- 칠판 가루는 단계 종료 후 가능한 경우 짧게 감쇠한다. 이 감쇠가 끝나기 전에 새 장면을 열거나 뒤로 이동하면 이전 가루 프레임을 취소한다. 감쇠는 가루가 실제 존재하고 효과가 허용된 경우에만 실행하며 4K 가루 비용 개선과 연결한다.

### 5.3 판서 접근성 및 보기 옵션 (C8, D2, D3, D6, D8, D9)

- `.board-area`의 랜드마크 이름을 유지하고 하위 칠판에 그림의 접근 가능한 이름을 제공한다. 현재까지 노출한 그룹을 사용해 질문, 본문, 음 순서·음높이, 화음 이름, 로마 숫자, 정리 문장을 수업 화면의 텍스트 설명으로 제공한다. 완료 또는 현재 시점까지 읽을 수 있게 표시된 항목에서 설명을 생성한다. 아직 가려진 정답과 이후 단계의 설명은 읽어 주지 않는다. 그림 설명과 대화형 음표 버튼을 나중에 함께 제공할 경우 음표 버튼을 `role="img"`의 하위에 넣지 않는다. 화면 읽기 알림은 프레임마다 갱신하지 않는다.
- `player.js`의 흰 보드 강조 토큰을 제안 색 `#a85400`에서 검토한다. 평평한 흰색 기준의 분석값과 별도로 실제 질감 배경에서 정상 크기 글자 4.5:1, 큰 글자 3:1을 확인한다. 키보드 포커스 표시의 대비, 고대비 화면 및 확대 시 글자·컨트롤 겹침도 확인한다.
- `scene-editor.js`의 `계이름(고정도) 표시`는 `계이름 표시`로 단순화하고 `도=C, 레=D` 도움말을 붙여 개념을 유지한다. 조표·음이름이 도입되는 단계에서는 음이름·고정도·이동도 레이블을 각각 정의한다.
- `hand.js`의 손 크기와 펜 끝 기준점을 분리해 손 이미지가 글을 가리는 폭을 줄인다. 손 보기에는 `자동 / 손과 펜 / 펜만`을 사용한다. 자동은 좁은 세로 판면에서 펜을 우선하고 가로·넓은 세로 판면에서는 손과 펜을 표시한다. 기존에 저장된 손과 펜·펜만 설정은 각각 교사의 선택으로 유지한다. 손을 그릴 때 소매 끝 윤곽을 칠판 경계의 클리핑 또는 사용자 콘텐츠를 가리지 않는 자연스러운 감쇠로 처리한다. 펜 끝 좌표와 획 끝 정합은 그대로 시험한다.
- 선 방식 설정은 `도움말`에서 `보기`로 이동하고 SVG·Canvas를 기존 설정 키로 읽을 수 있게 한다. 판서 효과를 `전체 / 간단 / 끔`으로 정의한다. 전체는 기존 손·가루 설정을 따르고, 간단은 펜·획만 표시하며, 끔은 요청한 단계를 즉시 그린다. 시스템의 동작 줄이기를 실시간 반영해 끔과 같은 시각 처리로 실행한다. 현재 브라우저 설정에 없는 새 값은 기존 기본 동작으로 해석한다. 구버전 백업의 옵션 검증과 새 필드의 내보내기 호환성은 백업 단계에서 동일한 버전 계약으로 시험한다.
- HTML 제목·설명, 자가 호스팅 또는 HTML 내장 사이트 아이콘과 도움말의 버전 표시를 정리한다. 버전은 `package.json`에서 빌드 시 주입한다. 수업 중 화면 유지 기능은 보기 메뉴에서 사용자가 켠 경우에만 요청한다. 지원 여부와 실제 획득 상태를 확인하고 탭이 숨겨졌다가 돌아오면 해당 옵션이 켜진 경우에만 재요청한다. 미지원·실패 상태에서도 수업의 진행 조작은 이용할 수 있다.

## 6. 3단계 · 손글씨와 화면 배치

대응 항목은 B1, A5, C9, D1이다. C3·C4·C10의 즉시 적용분은 1단계에서 먼저 반영한다. 3단계는 저장 형식 v1과 기존 판서 단계의 순서를 유지하면서 글자 렌더링, 줄바꿈, 편집 안내를 한 번에 교체한다.

### 6.2 판서용 획과 글꼴 빌드

1. `assets/`에 Gaegu Bold 원본 TTF를 고정 커밋의 SHA-256과 함께 두고, 원본에서 같은 글리프의 WOFF2를 만든다. 획 생성 도구는 TTF를 입력으로 쓴다. 원본 위치, 체크섬, 변환 도구 버전과 명령을 문서에 적는다. WOFF2 변환이나 서브셋으로 달라진 내부 이름은 그 글꼴의 배포 조건에 맞게 확인한다.
2. `tools/build-glyphs.mjs`에서 글꼴 cmap을 읽어 지원하는 한글 완성형, 영문·숫자·기호를 검출한다. 지원 목록과 JSON 키 순서는 코드포인트 순으로 고정한다. TTF와 대상 글자 목록이 같으면 결과 바이트도 같아야 한다. 현재의 `/home/claude/…` 경로와 `<글꼴 woff 파일>` 자리를 제거하고 `npm run glyphs`가 저장소 안의 입력을 사용하게 한다.
3. `src/glyph-data.json`에서 윤곽 경로 `d`를 제거한다. 단위와 글꼴 체크섬, 글자별 이동 폭 `a`, 중앙선 목록 `s`, 획 굵기 `w`, 마스크 경계 `bbox`를 사용한다. 덮임률은 생성 검수 결과로 집계한다. 마침표와 중점은 점 동작, 쉼표는 머리와 꼬리가 남는 짧은 동작을 검수한다. 중앙선 자동 추출 결과는 실제 필순과 비교하며, 계이름·대표 음이름·질문 접두어에서 재생이 부자연스러운 경우 해당 글자 경로만 교정한다.
4. `build.mjs`에서 WOFF2를 데이터 URL로 CSS에 넣고 CSS 글꼴 이름 `WhiteboardHand`를 고정한다. 가급적 Gaegu와 기기 기본 글꼴로 배포한다. 지원 밖 글자 검수에서 정상 표시가 확보되지 않으면 필요한 글자 범위의 Noto WOFF2를 상류 파일과의 대응이 확인된 상태에서 추가하고 용량 목표를 재측정한다. 사용 중 외부 글꼴 주소를 요청하지 않는다.
5. `document.fonts.load()`로 손글씨 글꼴과 번들에 포함한 대체 글꼴의 준비를 감지한다. 글자별 지원 여부는 획 자료와 같은 원본에서 만든 지원 목록을 기준으로 판단한다. 글꼴 로딩 결과 자체를 글자별 지원 여부에 사용하지 않는다. 글꼴 로드 실패 시 기기 글꼴로 표시하고 한 번 안내한다. 지연 로딩으로 표시 모드가 바뀌면 진행 위치를 보존해 배치를 한 번 갱신한다.

[Gaegu 원본 디렉터리](https://github.com/google/fonts/tree/main/ofl/gaegu) · [FontFaceSet.load의 텍스트 인자](https://developer.mozilla.org/en-US/docs/Web/API/FontFaceSet/load#parameters)

### 6.4 긴 문장 배치, 저장 정책과 편집 안내

1. `buildDocumentScene()`와 편집기 검사가 같은 조판 결과를 읽게 한다. 조판에는 실제 글꼴별 이동 폭, 문장 시작·끝 위치, 글자 크기, 줄 수, 글자·행 경계와 위반 내용을 담는다. 입력 시에는 조판만 갱신하고 실제 획·오선 도형은 미리보기나 수업 화면에서 생성한다.
2. 질문·정리 문장·본문은 명시한 줄바꿈을 존중한다. 각 줄은 공백을 우선으로 끊고, 긴 단어는 한 글자 단위 경계에서 나눈다. `Q.` 접두어는 첫 글자와 같은 줄에 배치하고 뒤쪽 줄은 접두어를 제외한 위치부터 시작한다. 표시할 수 있는 가로 폭과 세로 영역을 함께 검사한다. 본문 블록의 배치는 문자의 종류와 무관하게 조판이 반환한 실제 줄 수로 계산한다.
3. 질문의 초기 크기는 논리 단위 기준 세로 29·가로 36, 정리는 세로 25·가로 28로 시작한다. 폭 또는 할당 높이를 넘으면 논리 단위 1씩 크기를 줄이며 질문 22·정리 20·본문 20을 제안 하한으로 삼는다. 질문 2줄·정리 3줄·본문 영역의 온전한 높이를 만족하는 가장 큰 결과를 사용한다. 최종 하한은 휴대폰과 전자칠판 가독성 검수 결과로 기록한다.
4. `src/app.js`의 `layoutCheck()`가 하나의 예외를 던지는 방식에서 필드별 오류·경고를 돌려주는 방식으로 바꾼다. 저장·미리보기 공통의 문서 검증과 배치 검증을 호출한다. 가로에서도 하한 크기로 영역을 넘기면 새 저장은 필드 오류로 처리하며 기존 장면·기존 초안의 열기와 복구는 계속 허용한다. 가로에 맞고 세로에서만 넘치면 저장하고 편집기에 설명을 남긴다. 세로 재생에서 넘치는 해당 줄은 글자 경계에서 말줄임하며, 현재까지 공개된 문장의 전체 내용을 읽는 기능을 헤더에서 제공한다. 원본에는 전체 텍스트를 유지하고 화면 읽기용 설명은 공개된 그룹으로 제한한다.
5. 구조상의 글자 상한은 v1과 같은 질문 80자·정리 120자·블록당 80자·본문 합계 360자로 유지한다. 화면에 들어가는 분량은 조판 결과로 별도 계산해 `남은 글자 수`와 `배치 줄 수`로 표시한다. 입력 필드 근처 오류는 `aria-describedby`로 연결하며 IME 조합 중에는 상태 알림을 갱신하지 않는다. 오류는 저장 시 첫 해당 필드로 초점을 옮기고, 경고는 포커스를 빼앗지 않는다.
6. D1은 `src/scene.js`의 계이름·화음명·로마 숫자 영역부터 수정한다. 로마 숫자에는 손글씨 공통 자간을 줄이고 한 묶음으로 가운데에 정렬한다. 화음명과 강조 원은 논리 경계를 비교해 간격을 확보한다. 390×844에서 라벨과 로마 숫자는 실제 표시 크기 14 CSS px 이상을 목표로 한다. 오선·음표·라벨의 겹침 검사는 기본 장면과 현재 허용한 최고음·최저음으로 수행한다.

## 7. 4단계 · 들리는 판서

### 7.1 Web Audio 엔진 연결 (B2)

1. `git show 6804a36:src/lib/audio/engine.ts`에서 파형·필터·볼륨 엔벌로프·컴프레서·중지 로직을 가져와 `music-chalkboard-r1/src/audio/engine.js`에 옮긴다. 샘플 다운로드 없이 Web Audio로 소리를 합성한다. `src/theory/pitch.js`에는 같은 커밋의 `src/lib/theory/pitch.ts`에 있는 음높이 변환을 먼저 옮긴다. 음정·주파수는 여기서만 계산하고 그림 크기와 음이름 표시는 음향에 영향을 주지 않는다.
2. 엔진은 `unlockFromGesture()`, `play(notes, options)`, `stop()`만 호출하는 구조로 둔다. `play`는 MIDI 정수 0~127을 검사하고 `AudioContext.state === 'running'`일 때만 노드를 시작한다. 엔진에 DOM이나 저장소 접근을 두지 않는다. 자동 판서용 재생과 수동으로 다시 듣기는 소유자와 실행 토큰으로 구분한다. 단일 음은 약 0.65초, 동시 화음은 약 1.3초를 출발값으로 삼는다. 여러 음은 같은 `AudioContext.currentTime` 기준으로 시작하고, 음수에 따라 노트당 레벨을 낮춘다. 기본 컴프레서를 유지하며 동시 MIDI 발음은 16개 이하로 제한한다. 중지 시 빠르게 감쇠하고 끝난 발음 노드와 연결을 정리한다.
3. 헤더의 시작·이전/다음·재생·다시 듣기와 판서 음표 클릭, 건반 입력처럼 신뢰된 사용자 동작의 핸들러 안에서 첫 초기화와 `resume()`를 요청한다. 사파리에서 `AudioContext` 생성과 재개 요청은 첫 비동기 대기보다 앞서 실행한다. `app.js`는 시작 전에 `enabled` 설정을 읽고 새 기기 초기값은 켬으로 둔다. 차단·미지원은 판서와 분리하고 헤더에 `소리를 켜려면 눌러 주세요`처럼 상태를 한 번 표시한다. 최초 단계가 즉시 완료되는 등 해제 응답이 늦으면, 같은 장면·단계의 현재 실행 토큰이 유효하고 해당 재생 요청이 300ms 이내일 때만 이어서 소리를 시작한다. 그 밖의 지난 음은 버린다. 미지원 브라우저에서는 콘솔 오류와 반복 알림 없이 읽기와 편집이 계속된다.
4. 헤더 `판서` 메뉴에 `다시 듣기`와 `소리 켬/끔`을 추가한다. 소리 설정은 `settings`에 별도 키로 저장하고 이전 저장본에 키가 없으면 초기값을 사용한다. 저장소가 막히면 탭 세션에서만 설정을 유지한다. 끄는 즉시 예약과 현재 발음을 취소한다. 첫 배포에서는 브라우저의 기본 오디오 출력 정책을 사용한다. 운영 기기의 무음 모드와 스피커 출력은 실기기 확인 항목으로 둔다.

### 7.2 판서 이벤트와 취소

| 사용자 흐름 | 구현 계약 |
| --- | --- |
| 일반 판서 진행 | `scene.js`의 의미 그룹 중 실제 음표 머리에 `noteId`, 철자, MIDI와 재생 가능한 위치를 넣는다. `plan.js`에서 그 머리의 마지막 획 종료 시각을 찾고 `{ eventId, stepId, noteIds, midis, at }` 목록을 생성한다. `eventId`는 그룹과 실행 토큰으로 판별하고 렌더러의 `completeItem()`은 소리를 호출하지 않는다. |
| 단음·화음 | 한 열에 음 하나면 그 음이 완성될 때 울린다. 화음을 한 단계에 모두 쌓으면 마지막 머리 완성 시 구성음을 동시에 울린다. 구성음이 여러 단계로 나뉜 화음은 중간 단계에서 새로 그린 음을 개별 확인하고, 마지막 구성음이 그려질 때 실제로 완성된 화음을 한 번 울린다. 이름·조표·강조만 있는 단계와 본문 장면에는 자동 소리가 없다. 5단계에서 도입하는 명시적 듣기 순서가 있는 단계는 그 순서만 재생한다. |
| 다시 듣기 | 현재 단계의 이미 표시된 음을 악보 열 순서로 재생한다. 현재 단계가 설명만 있으면 직전 소리 있는 단계의 음 가운데 화면에 보이는 음을 대상으로 한다. 대상이 없으면 단추를 비활성화한다. 음표만 있는 열은 차례로, 화음 열은 표시된 구성음을 동시에 재생한다. 소리 끔 상태에서는 `다시 듣기`가 설정을 바꾸지 않으며 켜는 방법을 상태 줄로 안내한다. |
| 음표 선택 | 현재 보이는 음표 머리만 선택 가능하다. SVG·캔버스가 공유하는 판서 좌표와 음표 머리 바운드를 `player.js`에서 사용한다. 확대된 터치 영역이 겹치면 중심이 가장 가까운 하나를 고른다. 찍은 음만 재생하며 진행 상태는 바뀌지 않는다. 키보드 접근용으로 헤더 `판서 → 보이는 음 듣기`에 목록을 제공하고, 음이 많으면 열별로 묶는다. |
| 일시정지·재개 | `ScenePlayer`가 실제 진행 중 지나간 이벤트만 넘긴다. 일시정지하면 활성음·타이머를 끊는다. 재개는 아직 지나지 않은 이벤트만 계속한다. 정상 완료 직후 마지막 음의 감쇠는 이어지며, 다음 단계가 시작되면 앞 단계의 남은 소리를 끊는다. |
| 건너뛰기·이전·처음부터 | 강제 완료, 이전 그림 재구축, 처음부터 초기화는 조용히 처리한다. 다시 같은 단계를 명시적으로 재생하면 새 실행으로 들어간다. 화면 크기·테마·속도·렌더러 변경은 진행 위치를 복원하고, 이전에 소리 난 음은 다시 울리지 않는다. 재구축 과정에서 기존 음을 중지하고 남은 이벤트만 재개할 수 있게 처리한다. |
| 동작 줄이기·미리보기 | 동작 줄이기는 판서의 위치 계산을 생략해도 직접 시작한 단계의 정규 음 이벤트를 한 번 생성한다. 짧은 차례 재생과 화음 동시 재생을 그대로 따른다. 미리보기 진입과 종료에서는 재생을 중지한다. 미리보기에서 사용자가 직접 눌러 듣는 경우에는 미리보기 소유자로만 발음하고 수업 화면 복귀 시 취소한다. |
| 이탈·실패 | 장면 변경, 새 다시 듣기, 편집 진입, 문서 숨김, 음소거에서 실행 토큰을 폐기한다. 숨김에서 돌아오면 사용자가 직접 재개한다. `fullPlan()`, `rebuild()`, `seekLocation()` 및 호환 복구의 정적 그리기에는 음 판정이 없다. |

`drawAt(t,dt,quiet)` 한 개의 불리언으로 “손을 숨김”, “소리를 내지 않음”, “건너뛰기”를 함께 표현하지 않는다. 렌더링과 재생 제어를 분리하고 정상 tick의 `(이전 시각, 현재 시각]` 범위와 즉시 재생의 별도 경로에서만 이벤트를 내보낸다. 그래야 `finishStep()`의 마무리 그리기와 `resize()`의 시각 복원이 소리를 중복시키지 않는다.

### 7.3 완료 기준

- 기본 장면을 새 탭에서 자동으로 열면 소리 요청 0건이다. 사용자 시작 후 C4의 MIDI 60, A4의 MIDI 69·440Hz를 확인한다. 다장조 으뜸화음의 MIDI 60·64·67은 같은 시작 시각을 쓴다. 글 설명 장면에는 재생 요청이 없다.
- 주입한 테스트 엔진으로 한 프레임에 여러 판서 이벤트를 지나치는 경우, 최소화된 동작, 그리던 중 강제 완료, 이전→다시 진행, 미리보기→수업 복귀, 테마·화면 회전·속도 변경, 300ms 넘게 지연된 해제 응답을 검증한다. 같은 실행에서 음표별 자동 이벤트를 이중 호출하지 않고 취소된 실행은 재생 요청 0건이다.
- 헤더와 음표 터치에서 반복 들을 수 있고 음소거 직후 남은 음이 꺼지며 저장·검색·가져오기·발표용 키가 동작한다. Chromium 및 WebKit 브라우저에서 음향 상태·재생 요청을 자동 검사한다. iPhone Safari, Android Chrome, 전자칠판은 장치에서 첫 터치·재개·무음·수업 볼륨을 직접 확인하고 기록한다.

## 8. 5단계 · 악보·이론·수업

### 8.1 5A · 오선의 열과 음높이 모델 (B3)

확장 대상은 단일 높은음자리표와 온음표 모양을 사용하는 설명용 악보다. 1~8개 열, 열당 단음 하나 또는 3~4음 화음, 음역 C4~G6의 기보 위치, 올림표·내림표·제자리표, 조표, 음이름·계이름, 온음·반음 간격 표시를 구현한다. 장조 15개는 기존 계산기의 지원 키를 유지하고, 단조 첫 범위는 가자연단음계의 음이름과 온음·반음 표시에 둔다. 단음계 이동도와 화음 기능 표기는 사용할 교수법과 검산 규칙을 정한 뒤 적용한다.

| 파일 및 순서 | 변경 계약 |
| --- | --- |
| 1. `scene-model.js` | 장면 `schemaVersion: 2`를 추가한다. 기존 3개 `templateId`와 템플릿 선택 흐름을 유지하고 악보 템플릿은 `templateVersion: 2`를 사용한다. 악보 콘텐츠는 `key:{ tonic, mode }`, `columns:[{ id, kind:'note'\|'chord', notes:[{id,pitch}], ... }]`를 기본으로 한다. 본문 장면의 `blocks`와 템플릿 버전은 유지한다. 음높이 문자열은 철자와 실제 소리를 겸한다. 예를 들어 사장조 안 `F4`는 제자리표가 필요한 파이며 자동으로 F♯4로 치환하지 않는다. |
| 2. `scene-model.js` | 기존 단일 화음의 `note/<id>`, `name`, `roman`, `emphasis/chord`와 일반 음표의 `label/<id>`·`emphasis/<id>`를 보존한다. 이전 화음 열은 결정적 ID `legacy-chord`를 사용하고 별칭은 `activeGroups()` 및 렌더러가 같은 그룹 생성 함수에서 선택한다. 새 화음 열은 `name/<column-id>`, `roman/<column-id>`, `emphasis-column/<column-id>`를 쓴다. `staff` → `clef` → 선택된 `key-signature` → `note/<id>` 순서를 보장한다. 화음 이름·강조와 간격은 참조 음을 먼저 보이게 한다. |
| 3. `symbols.js`, `scene.js` | 자리는 글자·옥타브에서, 소리는 MIDI에서 구한다. 조표는 높은음자리표 뒤에 올림표 F–C–G–D–A–E–B, 내림표 B–E–A–D–G–C–F 순서로 배치한다. 조표 첫 선과 열 위치 사이에 여백을 예약한다. 본문과 같은 공용 레이아웃 진단 API를 사용한다. 4음 화음, 임시표 폭, 덧줄, 음이름 길이를 포함해 간격을 계산하고 세로에서 들어가지 않는 열은 편집기에서 장면 분할을 안내한다. |
| 4. `scene.js`, `plan.js` | 임시표는 악보상 왼쪽에서 오른쪽으로 같은 글자·옥타브의 현재 높임/낮춤을 추적한다. 처음 값은 조표에서 구하고, 이전 표기와 다른 경우에만 기호를 찍는다. 취소는 제자리표로 표시한다. 임시표 생략이 앞선 음표에 의존하면 앞 음을 먼저 내보내는 단계 제약을 둔다. 같은 열에 같은 글자·옥타브의 다른 변화음을 함께 쓰는 경우는 입력 오류로 표시한다. 음이름은 한글 또는 영문, 계이름은 기존 고정도와 조 기준 이동도를 용어와 함께 구별한다. |
| 5. `scene-editor.js` | 열 추가·삭제·순서 변경, 열별 음과 임시표 선택, 조·표시 이름·강조 선택을 기존 편집 창에 추가한다. 열을 이동해도 열·음·단계 ID와 기존 사용자 지정 단계는 유지한다. 삭제는 영향을 받는 표시·참조를 공유 모델의 `reconcileSteps()`에서 제거하고, 이제 비어 있는 단계와 연쇄 변경을 편집기에 설명한다. |

표기 시험은 C장조 `F#4 → F#4 → F4`에서 첫 올림표와 마지막 제자리표, G장조 `F#4 → F4 → F#4`에서 조표·제자리표·올림표를 확인한다. F장조의 조표는 B♭이고, 음표 `Bb4`의 렌더 위치는 B4와 같으며 MIDI는 70이다. `F#4`와 `Gb4`는 MIDI가 66으로 같고 오선 자리는 다르다. C장조 주요 3화음은 `[C4,E4,G4]` / `[F4,A4,C5]` / `[G4,B4,D5]`로 세 열을 만들고, `[G4,B4,D5,F5]`는 딸림7화음 한 열로 그린다. 장면 열이 화면에서 어떻게 들어맞는지는 PC 가로·폰 세로, 두 렌더러 및 두 테마에서 확인한다.

### 8.2 5A · 기존 장면·초안·백업 호환

1. 원본 `validateSceneV1()` 및 v1 초안 구조 검사를 버전별 진입점으로 남긴다. 저장소 읽기와 가져오기에서 원본 한도·형식 검사 → `upgradeSceneV1()`/ `upgradeDraftV1()` 실행 → v2 검증을 거친다. 변환은 같은 입력에 같은 결과를 내고 ID를 새로 발급하는 코드와 분리한다. v1 음 고르기는 음마다 안정적인 열 ID를 만들어 같은 순서로 옮기고, 화음은 기존 음 ID를 하나의 열에 넣는다. `revision`, `id`, `renderSeed`, 생성·수정·삭제 시각, 태그, 사용자 제목·질문·정리, `steps[].id`·`groupIds`·`advance`·`holdMs`를 보존한다. `showLabels`가 켜진 기존 음 고르기는 고정도 표시를 쓴다.
2. 초안은 `editorVersion: 2`로 동작한다. 제목이 비었거나 음 배열이 작성 중인 v1 초안도 자료와 참조를 유지한다. 구조가 안전한 초안에는 완성 장면 수준의 이론 정합성을 요구하지 않는다. `baseRevision`과 `draftId`는 저장된 초안을 단순 복구하는 경우 유지한다. 파일 가져오기의 새 초안 ID와 원본 분리 정책은 현재 API 동작을 유지한다.
3. 자동 일괄 덮어쓰기를 피한다. 목록·편집·판서 작업 진입 시 읽어서 변환하고, 사용자가 편집을 저장할 때만 v2 값을 쓴다. 원본 레코드와 충돌 비교는 같은 쓰기 트랜잭션에서 수행한다. 새 열·조·근거 유형이 있는 v2 백업은 패키지 `version: 2`를 사용한다. 기존 문법으로 완전하게 되돌릴 수 있는 장면에만 명시적 v1 호환 내보내기를 제공한다. 1·2 버전을 모두 가져오고, 유효하지 않은 v2 참조 하나가 있으면 데이터나 설정을 쓰기 전에 전체 파일을 거부한다.
4. 호환성 시험은 기본 장면 6종, 위치가 바뀐 사용자 지정 단계, 휴지통 항목, 본문, v1 초안, 전체·단일 v1 백업의 고정 입력을 사용한다. 그룹 시퀀스와 단계 경계가 동일하고 모든 음표 ID가 그대로인지 비교한다. v1 읽기·v2 저장·새로고침·재내보내기를 거친 뒤 음·문구·순서의 동등성을 검사한다. 변환에 실패하면 ID와 문제를 알리고 원본의 별도 보관 경로를 제공한다. 출시 전 신규 기능을 꺼도 IndexedDB와 데이터 v2를 읽는 호환 배포본을 준비한다. 기준 커밋처럼 DB 버전 1을 명시해 여는 빌드는 업그레이드 뒤 `VersionError`가 발생하므로 복구 대상으로 쓰지 않는다. 실제 브라우저 탭 A에서 v1 앱을 열고 탭 B에서 v2 앱을 시작해 연결 종료 및 차단·재시도 안내를 검증한다. 배포를 되돌린 뒤에도 v2 전용 수업과 초안, 휴지통 자료가 보존되어야 한다.

#### v1 화음 장면을 읽어 v2로 바꾸는 예

다장조 D4·F4·A4에 사용자가 잘못된 화음 이름을 쓴 v1 장면을 변환한 예다. 아래는 바뀐 필드와 보존할 그룹을 보여 주는 발췌다. 전체 저장 문서의 제목·초안·생성 시각 등은 8.2절 계약을 따른다.

```json
{
  "schemaVersion": 2,
  "id": "scene-re-minor-example",
  "revision": 4,
  "templateId": "chord-stack",
  "templateVersion": 2,
  "content": {
    "key": { "tonic": "C", "mode": "major" },
    "columns": [
      {
        "id": "legacy-chord",
        "kind": "chord",
        "notes": [
          { "id": "n1", "pitch": "D4" },
          { "id": "n2", "pitch": "F4" },
          { "id": "n3", "pitch": "A4" }
        ],
        "show": { "name": true, "roman": false, "emphasis": true },
        "legacyLabel": "으뜸화음"
      }
    ]
  },
  "steps": [
    { "id": "s1", "label": "오선과 음자리표", "groupIds": ["staff", "clef"], "advance": "manual", "holdMs": 0 },
    { "id": "s2", "label": "구성음", "groupIds": ["note/n1", "note/n2", "note/n3"], "advance": "manual", "holdMs": 0 },
    { "id": "s3", "label": "화음 확인", "groupIds": ["name", "emphasis/chord"], "advance": "manual", "holdMs": 0 }

```

`show`는 원래 장면의 표시 그룹 유무를 옮긴다. `legacyLabel`은 변환된 화음에서만 읽는 이전 이름이며 계산값이나 승인 상태로 사용하지 않는다. 일반 편집에서 쓴 메모는 별도 `teacherNote` 필드로 받는다. 자동 계산된 이름과 로마 숫자는 현재 조와 음을 바탕으로 렌더링 때 얻으며, 백업 파일의 원문을 사실 판단의 근거로 쓰지 않는다. 이 예에서는 변환 방법만 적용하면 저장된 리비전 4와 단계가 유지된다. 교사가 내용을 변경해 저장할 때 충돌 확인 후 리비전을 증가시킨다.

### 8.3 5B · 음악이론 검산과 화면 문구 (B4)

- `6804a36:src/lib/theory/{pitch,scale,korean,keyboard}.ts`의 순수 계산을 `src/theory/…`에 옮긴다. `6804a36:src/lib/script/validate.ts`의 철자·음정·화음 검사와 잘못된 입력 시험은 v2 모델의 경계에 맞춰 재사용한다. `chordNameKo()`, `chordNumeral()`는 옛 버전에서도 지원된 I·IV·V·V7만 확실히 계산한다. 장조에서 정확한 철자·구성음과 조가 일치할 때만 이론 라벨을 표시하고, 지원하지 않는 기능은 빈 이론 라벨과 편집 안내를 준다. 선택음·음계에는 도수, 음이름과 온음·반음 표기를 같은 모델의 결과로 제공한다.
- 화음 열의 이름은 자동 계산, 교사 메모, 이전 이름 검토 중의 구분을 둔다. 예전 이름이 계산과 일치하면 원래 표시 여부와 단계 순서를 유지한다. 불일치하면 원문을 편집창에 보관하고 해당 그룹에서 계산 가능한 설명을 쓰거나 검토 표시를 붙인다. 예를 들어 C장조 D4·F4·A4를 `으뜸화음`으로 저장했던 자료는 열 수 있으며, 판서에서는 확정 명칭 대신 `레·파·라 · 이름 검토 필요`를 표시한다. `내용 확인`에서 원문·계산 결과와 수정 위치를 보여 준다. 새 장면에서 자유 텍스트는 `교사 메모`로 입력한다. 음과 다른 자동 라벨을 구조화된 사실로 저장하거나 인증 표시를 받는 경로는 차단한다.
- 검산 결과는 `validateScene()`에서 오류(형식·참조·거짓 이론 선언)와 경고(미지원 화음, 이전 이름 검토)의 필드 경로와 함께 반환한다. `scene-storage.js`, 편집기, 판서 렌더링에서 규칙을 따로 구현하지 않는다. 검산 통과와 교사 검토 이력을 분리한다. 앱 기본 수업도 검산에 통과하면 `이론 계산 확인`으로 표시한다. `교사 검토 완료` 표시는 실제 검토 기록이 있는 해당 판본에 적용한다. 가져온 파일의 작성자 입력이나 검토 상태는 인증으로 취급하지 않고, 수정 시 승인된 판본과의 대응을 해제한다. AI로 만든 자료를 다룰 때는 출처가 그런 경우에만 `AI 초안 · 교사 검토 전`을 표시한다. 기존 자료를 AI로 분류할 근거가 없으면 일반 `검토 전`으로 둔다.
- 회귀 시험에는 C장조 I·IV·V·V7, G장조의 I/IV/V와 F♯ 이동도 `시`, F장조의 B♭ 이동도 `파`, C장조의 이동도 밖 F♯, 잘못 쌓은 화음, 이명동음 철자 비교, 가져오기에서 거짓 로마 숫자 선언을 넣는다. 예전 분석에서 확인한 D–F–A의 `으뜸화음` 오표기도 포함한다.

### 8.4 5C · 수업 묶음과 이전 수업 4편 복원 (B5)

1. `src/lesson-model.js`에 수업의 `{ schemaVersion:1, id, revision, origin, title, grade, sceneIds, createdAt, updatedAt }` 계약을 둔다. `sceneIds`는 순서가 있는 1~50개 고유 ID 목록을 기본으로 하며 내 장면과 내장 장면을 함께 담을 수 있다. 학교급은 `공통`, `초5-6`, `중1-3`, `미지정` 중 하나다. ID에서 실제 장면을 가져와 의미 검사를 한다. 같은 수업 안에서 내용 편집 후 재사용하면 다음 열기에서 최신 장면을 보여 준다. 앱 제공판은 코드로 등록하고 강사 수정은 복제본에서 수행한다.
2. IndexedDB 용기에 버전 2로 `lessons` 스토어를 추가하고 키는 `id`로 둔다. 변경은 수업 revision을 비교한다. 이전 앱 탭의 업그레이드 차단과 읽기 실패를 현재의 `onversionchange`·`onblocked` 처리로 안내한다. 수업이 가리키는 장면을 휴지통으로 보내면 수업 관리의 해당 자리에 `휴지통에 있음`을 표시하고 복원·다른 장면 선택 경로를 둔다. 영구 삭제는 참조 중인 수업을 보여 주고, 명시적으로 제거하는 경우에는 수업 목록 변경과 영구 삭제가 같은 트랜잭션에서 완료되도록 한다. 참조 제거로 비는 수업에 대해서는 대체 장면 선택을 요구한다.
3. 수업 내보내기는 해당 수업이 참조하는 모든 사용자 장면을 함께 담는다. v2 수업 파일은 모든 참조가 유효한 내장 장면인 경우에만 장면 0개와 수업 1개 이상을 허용한다. 내장 장면은 안정적인 내장 ID로 확인하고 없는 내장 ID나 사용자 장면을 참조하는 파일은 적용 전 오류로 표시한다. 가져오기에서 현재 장면 복제 규칙을 재사용하고 장면·수업 ID 매핑을 한 번 만든 후, 모든 순서를 새 ID로 갱신한다. 분할 백업은 상호 참조하는 수업·장면을 같은 파일에 넣는 것을 기본으로 한다. 해당 묶음이 기존 5 MiB 또는 파일당 장면 500개 한도를 넘으면 정상적으로 나눌 수 없는 이유와 장면만 개별 백업하는 선택지를 안내한다.
4. `app.js`의 헤더 `장면`에 `수업 열기·관리`를 넣는다. 수업을 열면 그 수업의 순서가 장면 이동에 사용되고 기존 단일 장면 진행과 중복 실행되지 않는다. 이전·다음 **단계**는 장면 내부, 이전·다음 **장면**은 수업 순서에만 적용한다. 맨 끝에서 수업 완료를 표시한다. 활성 수업 ID와 장면 ID는 저장해 다시 열 수 있다. 연습 응답은 현재 화면 상태에만 둔다.
5. `6804a36:src/lessons/{names-and-solfege,c-major-scale,c-major-triads,dominant-seventh-cadence}.ts`의 대본을 재구성한다. 원본 `show`는 보여 줄 그룹, `set`은 라벨과 간격, `highlight`는 대상 음 ID, `play`는 음향 이벤트, `ask`는 건반 문제로 대응시킨다. v2 장면 그룹은 한 화면에 한 번 판서된다는 계약을 유지한다. 이미 판서한 내용이 사라지거나 다시 보이는 원본은 새 장면으로 분리하고 앞 단계의 상태를 재구성한다. 예를 들어 마침꼴 두 번째 단계는 앞의 딸림3화음을 가리고 딸림7화음을 표시한다. 이 전환은 다음 장면의 시작 내용으로 매핑한다. 마침꼴의 소리 순서는 V7 동시 발음 → I 동시 발음이다. 단계의 선택적 `cue`를 정의한다. `{ type:"listen", targets:[{ columnId }] }`는 열 순서 또는 교사 지정 순서로 발음한다. `{ type:"practice", order:"free", keyboard:{ from:"C4", to:"G5" }, columnIds:[…] }`는 건반 범위와 답 참조를 담는다. 읽기 시 `type`과 각 필드를 허용 목록으로 검사하고 실제 장면에서 찾은 ID로만 판정한다. `groupIds`가 빈 단계는 유효한 `cue`가 있을 때만 허용한다. 해보기 단계는 자동·연속 모드에서도 교사가 진행할 때까지 기다린다. 기존 내장 장면 6종의 장면 ID를 유지한다. 새 수업에 들어가는 내장 장면과 단계·음표·열의 ID도 고정한다. 시작할 때 매번 ID를 만드는 현재 기본 장면에는 기존 링크와 저장된 장면 ID를 깨지 않으면서 내부 ID를 고정하고, 수업 자료에는 일정한 ID의 검수 표본을 사용한다.

## 9. 6단계 · 저장·복구·공유

기기 내 저장을 기본으로 두고, 파일 백업과 초안 복구를 먼저 보완한다. 짧은 공유 링크는 별도 작업으로 배포한다. 진입점은 헤더의 `장면` 메뉴와 그 안의 수업 관리에 둔다. 백업·초안 안내는 헤더 상태와 임시 대화창에서 확인할 수 있게 한다.

### 9.1 데이터 경계와 호환성

| 구분 | 기준 커밋에서 읽는 형식 | 이 단계의 계약 |
| --- | --- | --- |

1. `src/scene-storage.js`의 파일 디코딩, 구조 검증, 문서 검증, 쓰기 트랜잭션을 분리한다. 파일과 링크는 크기 검사 → JSON 파싱 → 깊이·노드 수·금지 키 검사 → 버전별 허용 키 검사 → 정규화 및 최신 문서 검증 → 사용자 미리보기 → 단일 쓰기 트랜잭션 순서로 처리한다. 파일 검증은 현재의 파일당 5 MiB·장면 500개·활성 장면 총 1,000개와 깊이 20·노드 수 150,000·단일 문자열 20,000 코드 단위·한 객체의 항목 10,000 제한을 유지한다. 트랜잭션이 완료된 시점에 한해 성공을 알린다.
2. `src/scene-model.js`가 템플릿, 글자 수, 구조 제한, ID·그룹 참조 규칙을 제공한다. 초안은 빈 제목·입력 중인 음 값처럼 아직 저장할 수 없는 입력도 구조상 안전하면 보관한다. 장면 저장은 완성된 내용, 그룹 의존성, 이론 검증까지 확인한다. 공통 필드 사전으로 중복을 줄이면서 단계별 검증 강도는 유지한다. `src/import-settings.js`의 허용 옵션 목록을 시작 시 설정 복원과 파일 설정 검사에서 공유한다. 기존 v1 파일의 허용 값과 필수 키는 회귀 표본으로 고정한다.
3. 설정은 가져오기 대화창에서 기본 해제한다. 선택한 설정만 해당 장면·수업·순서와 같은 트랜잭션에 기록하고 완료 후 재생기에 반영한다. 보류·실패·취소 시 장면 목록, 화면 설정과 현재 장면을 유지한다. 레코드가 깨졌거나 이후 버전이면 저장본을 보존한 상태로 목록에 오류를 표시하고 검증된 다른 장면은 계속 열 수 있게 한다.
4. 장면 순서에도 동시 쓰기 검사를 적용한다. 현재 `reorderScenes`는 장면 ID 집합만 비교해 같은 목록의 순서를 두 탭에서 바꾸면 나중 저장이 앞선 변경을 덮어쓴다. 목록을 읽을 때 `meta.sceneOrderRevision`의 값(기존 DB는 `0`)을 함께 반환하고, 재정렬은 예상 리비전과 ID 집합을 둘 다 비교한다. 순서 변경, 추가·가져오기, 휴지통 이동·복원·영구 삭제처럼 목록이 변하는 쓰기와 같은 트랜잭션에서 값을 증가시킨다. 불일치 시 최신 순서를 다시 보여 주고 사용자가 이동을 다시 선택하게 한다.

### 9.2 저장 유지와 파일 백업 · B6, D7

**저장 유지.** `src/app.js`에서 저장소 초기화가 성공하면 지원되는 경우 `navigator.storage.persisted()`를 읽는다. 헤더 `장면 → 저장 상태`의 명시적 `저장 유지 요청` 동작에서 `persist()`를 호출하고 승인·미승인·미지원·조회 실패를 구분한다. 권한 결과는 현재 창에서 확인하고 조회 실패나 미승인 상태에서도 편집과 백업을 계속할 수 있어야 한다. `QuotaExceededError`나 DB 차단 시 입력값을 메모리에 유지하고, 저장 오류를 고정 알림으로 표시하며, 초안 JSON을 별도로 내보낼 수 있게 한다. 저장 유지 권한은 브라우저 정책과 사용자 사이트 데이터 삭제의 영향을 받는다. 초기 계측은 Playwright WebKit에서 기능 분기를 확인하고, 휴대전화 Safari 일반 탭·홈 화면 추가 상태·사생활 보호 탭에서 실제 동작을 기록한다. 첨부 분석에 인용된 Safari ITP의 7일 사례는 Safari 사용일과 상호작용 조건이 있는 정책 참고다. [WebKit 저장 정책](https://webkit.org/blog/14403/updates-to-storage-policy/) · [WebKit 추적 방지 정책 설명](https://webkit.org/blog/10218/full-third-party-cookie-blocking-and-more/)

**백업 생성과 저장.**

1. `src/backup-chunks.js`의 파일 분할을 유지하되, 대화창에서 활성 장면 수·수업 수·파일 수·휴지통 및 보기 설정 포함 여부를 먼저 보여 준다. `초안은 장면 백업에 포함되지 않습니다. 초안 복구에서 별도로 내보낼 수 있습니다.`를 안내한다. 준비된 파일은 같은 스냅샷의 장면·수업·보기 설정으로 만든다. 배치 중 설정을 다시 읽어 결과가 달라지지 않도록 `scenes`, `lessons`, `settings`, `meta`를 같은 읽기 트랜잭션에서 조회한다.
2. 여러 파일에 수업이 포함되면 각 수업과 그 수업에서 참조하는 사용자 장면을 같은 파일에 담는다. 사용자 장면을 공유하는 수업끼리는 연결된 묶음을 만들어 함께 분할한다. 대상에 휴지통이 포함되지 않고 수업에 휴지통 장면 참조가 남아 있으면 누락을 조용히 제거하지 말고 수업 목록에서 해결 방법을 제시한다. 해당 묶음이 파일 한도를 넘어가면 장면만 내보내는 경로와 수업별로 선택하는 경로를 제공한다. 조각마다 `backupSet:{ id, part, total }`와 파일 안 장면의 원본 순번을 v2 메타데이터로 기록한다. 같은 집합의 전체 복원은 중복 조각·순번과 누락 여부를 확인하고 원본 순서로 정렬한 뒤 적용한다. 각 조각만 가져올 때에는 그 파일의 사본만 복원된다고 안내한다. 구형 분할 파일은 치환하지 않고 기존 개별 가져오기로 읽는다. 예상 바이트로 분할한 뒤 확정 JSON의 UTF-8 크기와 장면 수를 다시 검사한다.
3. 파일명은 한국 표준시 날짜를 사용해 `음악칠판_전체백업_YYYY-MM-DD_01-of-03.json` 형식으로 제안한다. 장면·초안 이름에서는 파일 시스템 예약 문자 및 제어 문자를 제거하고 최대 길이를 제한한다. 각 파일은 한 번의 사용자 동작으로 내려받게 하고 브라우저가 내려받기를 차단하는 경우를 위해 `JSON 내용 복사`와 기기가 지원할 경우 `파일 공유`를 제공한다. 다운로드 요청과 실제 저장 확인은 구분한다. 파일 공유는 `navigator.canShare({ files })`를 확인하고 버튼 동작에서 호출한다. 클립보드 권한을 받지 못하면 읽기 전용 텍스트 선택으로 이어진다.
4. `meta.lastConfirmedBackupAt`과 백업 범위를 기록한다. 모든 분할 파일에 대해 저장 또는 복사 동작을 요청한 뒤 사용자가 `모든 백업 파일을 보관했습니다`로 확인할 때 날짜를 갱신한다. 개별 장면·초안 내보내기는 전체 백업 날짜를 바꾸지 않는다. 마지막 확인 날짜와 경과일을 저장 상태에 표시한다. 사용자 장면이 생긴 지 7일 이상 백업이 없거나 마지막 확인부터 7일이 지난 경우, 새 수업을 시작하기 전 조용한 헤더 안내를 표기한다. 7일은 앱의 제안 기본값이며, 안내를 닫아도 백업 메뉴와 최근 확인 날짜를 확인할 수 있다.

### 9.3 초안 복구와 동시 편집 · C6

- **발견.** 앱 시작 시 삭제되지 않은 초안이 있으면 헤더 `장면 → 초안 복구`에 수를 표시한다. `src/app.js`에서 편집할 때 현재 `clientId`를 접두사로 한 초안 키 하나만 조회하는 대신, `draft.sceneId === original.id` 조건으로 후보를 찾는다. 기존 탭별 레코드는 그대로 읽고, 후보가 여러 개면 최신 순의 제목·수정 시각·원본 상태로 구별한다. `sceneId: null`인 새 초안은 목록에서 다룬다.
- **복구.** `baseRevision`이 살아 있는 원본의 `revision`과 같으면 `이어서 편집`과 `저장본 열기` 중 선택한다. 그 사이 원본이 변경·삭제되었거나 파일로 가져온 초안이면 `새 장면으로 이어서 편집`을 제공한다. 가져온 초안의 `sceneId`와 `baseRevision`은 `null`로 초기화하고 새 `draftId`와 현재 세션의 `clientId`를 부여한다. 본문의 음표·단계 ID와 그룹 참조는 유지한다. 형식이 유효한 초안은 제목이 비어 있어도 복구한다.
- **동시성.** 다른 세션의 초안을 복구하면 새 편집 세션 ID로 자동 저장하고 선택한 원본 초안의 키와 열었을 때의 스냅샷을 별도로 기억한다. `src/scene-editor.js`의 800ms 자동 저장 대기와 직렬 쓰기 큐를 이어받는다. 저장·닫기·삭제 전 타이머를 취소하고 진행 중 쓰기를 기다린다. 저장 성공 시 `saveScene` 트랜잭션에서 해당 세션 초안을 지우고, 복구의 출처 초안은 ID·기준 리비전·수정 시각·내용이 선택 시점과 같은 경우에만 함께 지운다. 원본 장면을 공유하는 다른 초안과 선택 이후 변경된 초안은 목록에 남겨 `원본 변경됨` 상태를 표시한다.
- **삭제.** 목록에 `파일로 저장`과 `초안 삭제`를 제공한다. 삭제 요청에 사용자가 확인한 레코드의 버전 비교 조건을 포함해, 확인 창이 열린 동안 다른 탭이 덮어쓴 최신 내용이 지워지지 않도록 한다. 충돌 시 최신 목록을 다시 보여 준다. 저장한 장면과 해당 수업의 순서에는 영향을 주지 않는다. 편집 중 `변경 버리기`를 선택했을 때 이번 세션 변경만 지울지, 복구해 온 초안까지 지울지 UI 문구에서 구분한다.

### 9.4 앱 안 확인창과 가져오기 · C7

1. `src/ui/confirm-dialog.js`에 공통 `<dialog>`를 둔다. 제목·설명·초기 포커스·실행·취소를 호출부에서 정한다. 템플릿 변경, 단계 초기화 및 영구 삭제는 취소 쪽에 먼저 초점을 둔다. Esc·취소는 같은 결과로 처리하고 호출 요소가 남아 있으면 초점을 돌린다. 확인 후 비동기 쓰기 중엔 재실행을 막고 완료 뒤 성공을 알린다. 닫는 동안 앱 전역 단축키도 멈춘다.
2. `src/scene-editor.js`의 템플릿·판서 순서 변경, `src/ui/scene-list.js`의 휴지통·영구 삭제, `src/app.js`의 충돌 사본·초안 복구·파일 가져오기에 연결한다. 오류·빈 목록은 1단계의 화면 알림과 각 대화창 안 상태로 표시한다. 대화창에 전달한 장면 제목은 텍스트 노드로 삽입한다. 에디터에서 확인창을 닫으면 같은 입력 값과 포커스가 살아 있어야 한다.
3. 가져오기 확인창을 하나로 통합한다. 파일명, 종류와 형식 버전, 장면 수, 수업 수, 휴지통 포함 여부, 최대 5개 예시 제목을 보여 준다. `새 사본으로 가져오기` 전에는 DB를 쓰지 않는다. 손상되거나 형식이 지원되지 않는 입력의 경우 파일 선택을 다시 할 수 있게 한다. v2 전체 백업 복원에서는 조각을 함께 선택하게 하고 쓰기 전에 전체 세트의 검증을 완료한다. 기존 사용자 장면 1,000개 한도와 중복 ID, 수업 참조, 보기 설정을 전체 기준으로 다시 검증하고 같은 쓰기 트랜잭션으로 반영한다. 파일이 정상이어도 저장 권한이 제한된 환경에서는 미리보기와 JSON 복사 경로를 이용할 수 있게 한다.

### 9.5 짧은 링크 공유 · B6

1. `src/share-link.js`에 장면 링크 코덱을 둔다. 1차는 단일 저장 장면 또는 기본 장면을 공유한다. 5단계 수업 모델과 참조 검증이 안정화되면 같은 경로로 짧은 수업과 필수 장면을 같이 공유한다. 긴 수업은 `수업 파일 내보내기`로 이어지게 한다. 로컬 DB의 참조만 담아 다른 브라우저에서 자료가 열리지 않는 링크를 만들지 않는다.
2. 링크의 JSON 허용 키는 장면형 `{version: 1, kind: 'scene', scene}`과 수업형 `{version: 1, kind: 'lesson', lesson, scenes}`으로 분기한다. `scene`은 `schemaVersion`, `templateId`, `templateVersion`, `title`, `tags`, `question`, `caption`, `content`, `steps`, `renderSeed`를 담는다. 수업형에서 `lesson`은 `{title, grade, sceneRefs}`, `scenes`는 `{ref, scene}` 배열이다. 링크 안에서만 유효한 `ref`를 중복 없이 부여하고 `sceneRefs` 순서대로 연다. 장면의 DB ID·작성 시각·리비전·가져오기 이력, 초안·휴지통·보기 설정과 검토 상태는 제외한다. 장면 내부 음표 ID와 단계 그룹 참조는 유지한다. 받는 쪽에서 읽기용 임시 식별자와 메타데이터를 새로 부여하고 `validateScene`과 5단계의 수업·참조 검증을 거친다. 링크 제작에 앞서 `링크를 받은 사람은 담긴 내용을 볼 수 있습니다.`와 제목·포함 자료 수를 표시한다.
3. UTF-8 JSON을 패딩 없는 Base64URL로 인코딩하고 `#mwb1=<payload>`로 붙인다. 공유 링크의 **전체 URL 길이 4,096자**, **디코딩한 JSON 3,072바이트**를 앱의 초기 상한으로 둔다. 전체 URL에는 도메인·경로·프래그먼트 이름도 포함되므로 두 한도를 별도로 검사한다. 일부 메시지 앱이 더 짧은 문자열만 전달할 수 있어 파일 사본이 대체 경로다. 표준 HTTPS 배포에서만 링크 생성 기능을 노출한다. 프래그먼트는 서버 HTTP 요청에 포함되지 않는다. 링크 자체에는 자료가 들어 있으므로 만료·회수 기능을 표시하지 않고, 사용자가 링크를 보낼 때 해당 사실을 안내한다. [URI 프래그먼트 설명](https://developer.mozilla.org/en-US/docs/Web/URI/Reference/Fragment)
4. 링크를 받으면 길이·형식·Base64URL 문자 → 디코딩 바이트 → 엄격한 UTF-8/JSON → 허용 키·버전·장면/수업 검증 순으로 처리한다. 정상 링크는 읽기 전용 미리보기로 열고 `내 장면에 사본 저장`에서만 ID를 새로 만들어 쓴다. `lastSceneId` 업데이트도 미리보기 중에는 건너뛰며, 닫으면 이전 장면과 진행 위치를 복원한다. 미리보기 종류를 헤더에 표시한다. 알 수 없는 링크 버전이나 잘린 링크는 현재 장면을 그대로 두고 오류 및 파일 열기 경로를 안내한다.

### 9.6 정적 배포의 CSP · C12

- `src/scene-editor.js`와 `src/ui/scene-list.js`에서 동적으로 생성하는 `<style>`을 `src/style.css`의 각 화면 범위로 옮기고, 오류 메시지의 문자열 인라인 스타일은 클래스로 바꾼다. `build.mjs`가 이스케이프와 줄바꿈 정규화를 끝낸 인라인 JS·CSS의 실제 UTF-8 바이트로 SHA-256 해시를 계산한다. `src/index.html`에서 스타일과 스크립트보다 앞에 메타 CSP를 둔다. 기준 후보는 `default-src 'none'`, `script-src 'sha256-…'`, `style-src 'sha256-…'`, `font-src data:`, `img-src 'self' data:`, `connect-src 'none'`, `object-src 'none'`, `base-uri 'none'`, `form-action 'none'`이다. 사용 중인 글꼴·아이콘 방식에 맞춰 실제 필요한 소스만 확정한다. 렌더러가 계산한 동적 위치, 인라인 SVG, 폰트, Blob 파일 내보내기, Web Audio는 Chromium과 WebKit에서 회귀 검증한다. [CSP 지시어 및 인라인 해시](https://developer.mozilla.org/en-US/docs/Web/HTTP/Reference/Headers/Content-Security-Policy)
- 호스팅 헤더를 쓰는 경우 메타와 상충하는 정책이 없는지 확인한다. 프레임 포함 범위는 검증된 배포 설정으로 결정하며, `frame-ancestors`가 필요한 경우 HTTP 헤더에서 관리한다. 출처 설정과 헤더 값은 프리뷰에서 응답 및 콘솔로 확인한다. 파일과 링크 데이터의 검증, DOM 텍스트 사용과 URL 크기 검사도 계속 적용한다.

## 10. 공통 코드 정리와 검색

### 10.1 중복 줄이기 · C11

1. 새 동작을 넣는 파일의 관련 함수부터 읽기 쉽게 정리한다. C1의 회귀 시험이 통과한 후 서식 정리만 담은 커밋과 동작을 바꾸는 커밋을 구분한다. Node 24.x를 `package.json`의 `engines.node`와 CI에 맞추고 Node의 esbuild API 또는 프로젝트 로컬 실행 파일을 사용한다. 로컬 설치가 없으면 설치 명령을 안내하고 실패를 반환한다. 도구의 절대 경로와 시제품 전용 `window.__r1` 의존을 정리한다.
2. 장면 ID의 유일성, 가져오기 중 ID 매핑, 같은 브라우저 탭을 추적하는 client ID의 서로 다른 목적을 확인한다. 생성 규칙은 공통화하되 이미 저장된 ID와 단계의 참조는 보존한다. 템플릿·음과 화음·보기 설정의 기본값 및 허용 목록은 해당 모델에서 정의한다. 장면 공통 검사 결과를 편집기와 파일 가져오기가 같이 사용하고, 메시지와 저장 가능한 초안 정의는 호출 모드로 구별한다.
3. 실제 참조를 확인한 후 R1의 `buildScene`·`SCENES`·`QUESTION`, `.hud`, 쓰이지 않는 `applyImportedSettings`와 샘플 SVG를 정리한다. 기존 `plan.test.mjs`에서 쓰는 R1 장면은 현재 기본 장면을 사용하는 동등한 테스트로 전환하고 판서 계획의 검증 범위를 비교한다. 사용처 검색과 빌드 산출물 확인을 모두 통과할 때 제거한다.
4. 린트 규칙은 새 코드와 편집한 파일에 적용한다. 형식 정리는 별도 변경으로 되돌릴 수 있게 두고, 타입 검사를 도입한다면 장면·재생·저장소 모듈의 JSDoc 계약부터 시작한다. 폴더 이름 `music-chalkboard-r1` 변경은 호스팅 경로와 문서 링크가 연결돼 있으므로 후속 배포 작업으로 다룬다. 레거시 복구 참조는 설계에서 커밋 `6804a36`으로 고정하고 공개 태그를 만드는 일은 저장소 정리 작업에서 검토한다.
5. `dist/index.html`은 단일 HTML 배포 계약을 유지한다. 0~1단계는 추적본과 재빌드를 비교한다. Vercel과 배포 이외의 저장소 소비자가 CI 빌드로 동일 결과를 사용할 수 있는지 확인한 후, 별도 PR에서 `dist/` 추적 해제 또는 명시적 추적 유지 중 하나를 결정한다. 추적을 해제하는 경우 배포 체크는 산출물 바이트 비교 대신 고정 환경에서 연속 두 빌드의 해시 일치와 생성 파일 존재를 확인한다.

### 10.2 검색과 표기 · D4

`src/ui/scene-list.js`의 `searchScenes`에서 검색 원문과 비교 문자열을 분리한다. 기존의 제목 우선·찾은 순서·결과 제한은 그대로 적용하며, 각 검색 필드에 NFC 정규화와 공백·가운뎃점 계열 구분 기호만 제거한 비교 문자열을 추가한다. 빈 검색어와 한글 조합 중 입력은 기존 처리와 동일하다. `도미솔`이 `도·미·솔`을 찾고 `C#`, `C`, `Bb`, `B`, `V7`, `V`가 각각 제목 우선순위와 음악 의미를 유지하는지를 시험한다. 광범위한 기호 삭제나 정규식 인젝션을 막도록 검색어는 리터럴 문자열로 비교한다. 화면 이름은 `음악 칠판 튜터`로 통일하고 풀어 쓸 경우 `인터랙티브` 표기를 적용한다.

### 11.3 기능 교차 회귀

- 새 장면을 만든 뒤 미리보고, 돌아와 수정하고 한 번만 눌러 저장한다. 새로고침 후 장면을 열어 원래 글과 단계 순서를 확인한다.
- 다른 탭에서 현재 장면을 삭제하거나 업데이트한다. 수업 화면의 이전·다음은 실제 목록과 일치하고, 편집 탭에는 revision 충돌이 표시된다. 열기·가져오기 실패 뒤 기존 칠판과 제목을 확인한다.
- 파일 1개가 여러 장면을 포함하고 일부가 유효하지 않으면 저장 내용·순서·보기 설정에 부분 적용된 것이 없는지 확인한다. 1,000개 분할 백업과 불완전 세트, 오래된 형식과 새 형식을 각각 시험한다.
- 장면 전환, 이전 단계, 처음부터, 바로 완성, 픽셀 크기 변경, 배경 탭, 미리보기 종료 뒤 각 상태에서 남은 음이나 중복 알림이 없는지 검사한다.
- 자산 바뀐 뒤 글꼴을 불러오지 못하는 상태에서도 글이 남고 글줄·선택 영역이 판에 맞는지 확인한다. 글꼴 표시 및 라이선스 안내는 인터넷 연결 없이도 열려야 한다.

## 12. 운영 배포와 되돌리기 · A9

1. 현재 운영 도메인과 기준 배포 ID·Git SHA·Node 버전을 배포 기록에 남긴다. Vercel의 `Root Directory`, 설치 명령, 빌드 명령과 출력 폴더를 실제 설정 또는 빌드 로그에서 읽는다. 탐색 결과에 없었던 설정값은 추정해서 덮어쓰지 않는다. [Vercel 현재 배포](https://vercel.com/kimyounggaurs-projects/music-education-whiteboard-tutor/8LmLzgmc7ks5UmMivCT8YMAfZ8Jm)
2. 하위 앱을 루트로 쓰는 설정을 확인하면 그 위치의 `vercel.json`에 `installCommand: npm ci`, `buildCommand: npm run build`, `outputDirectory: dist`를 둔다. 저장소 루트를 쓰는 설정을 확인하면 루트 설정에 `npm --prefix music-chalkboard-r1 ci`, `npm --prefix music-chalkboard-r1 run build`, `music-chalkboard-r1/dist`를 쓰는 안을 검증한다. 두 방식 중 하나를 택해 Preview에서 잠금 파일과 생성 HTML이 일치하는지 본다. [Vercel 프로젝트 설정](https://vercel.com/docs/project-configuration)
3. 단계별 PR에서 CI와 Preview를 같은 커밋으로 확인한다. 앱 시작·도움말의 버전·장면 만들기·백업을 합성 데이터로 시험하고, 승인된 릴리스만 운영에 반영한다. Preview와 운영은 주소가 달라 로컬 저장소 역시 별개이므로 기존 운영 사용자의 저장 호환은 동일한 로컬 오리진에서 구버전 파일로 장면을 만든 뒤 신버전 파일로 교체하는 시험으로 확인한다. 운영 적용 후에는 합성 자료를 쓰는 전용 브라우저 프로필로 스모크 테스트한다. 운영 주소는 시크릿 창이나 로그인하지 않은 기기에서도 열어 실제 헤더와 버전을 확인한다. 배포 상태 `READY`와 운영 도메인의 페이지 동작은 각각 기록한다.
4. 운영에서 재생·저장·복원 기본 흐름이 실패하면 원인과 데이터 영향부터 구분한다. 표시·음향 문제는 직전 호환 배포로 복구하거나 해당 기능을 해제한다. v2 DB가 이미 열렸다면 v1 전용 빌드로 돌아가지 않는다. 같은 DB 스키마를 읽을 수 있는 복구 빌드로 되돌리고 v2 전용 레코드를 보존한다. 기존 Vercel Git 자동 도메인 할당은 rollback 이후 상태를 다시 확인한다. 저장소나 공개 보호 정책을 조정해야 하는 경우에는 별도 운영 결정으로 처리한다. [Vercel 되돌리기](https://vercel.com/docs/instant-rollback)
