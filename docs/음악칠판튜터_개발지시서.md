## 1. 한눈에 보기

- 만들 것: 교사가 교실 화면에 띄워 쓰는 음악 수업 칠판. 수업 대본(데이터)을 앱이 오선보·건반·소리로 바꿔 한 단계씩 보여 준다.
- 1단계 목표: 검증 수업 4편이 PC와 휴대폰 브라우저에서 처음부터 끝까지 돈다.
- 1단계에는 AI 호출, 로그인, 저장, 서버 기능이 없다. 수업 대본은 앱 안의 파일이다.
- 서비스 이름은 미정이라 화면에는 "음악 칠판(가칭)"으로 쓴다.

## 2. 범위

만든다

1. 수업 고르기 화면: 학교급 묶음별 목록, "교사 검토 전" 표시
2. 수업 화면: 오선보, 건반, 자막, 강조, 소리
3. 진행: 이전·다음·처음으로, 단계 표시, 방향키와 발표용 리모컨 키, 터치
4. 해보기: 건반을 눌러 답하고 맞았는지 바로 확인
5. 수업 대본 형식 v1과 검산기(빌드와 테스트 때 자동 검사)
6. 검증 수업 4편(9장)
7. 큰 화면(PC, 전자칠판, TV)과 휴대폰(가로·세로) 화면
8. 링크로 접속: 수업별 주소, 단계 주소(`?step=3`)
9. 칠판(어두운 초록)과 화이트보드(밝음) 두 가지 색 테마

만들지 않는다

- AI 자유 질문, 로그인, 수업 저장, 데이터베이스
- 리듬·국악·낮은음자리표, 펜 판서, 음성 해설, 학생 기기 참여
- 방문자 통계, 광고, 외부 글꼴·CDN 등 실행 중 외부 요청

완료 기준(기획서 11장과 같음)

1. 4편 모두 끝까지 진행되고 검산기를 통과한다.
2. PC와 휴대폰 브라우저에서 소리·터치·방향키가 정상이다.
3. 실제 교실 화면에서 한 번 이상 시연한다. (사람이 해야 함)
4. 초등 교사와 중학교 음악 교사를 포함해 3명 이상에게 보여 주고 의견을 받는다. (사람이 해야 함)

## 3. 기술 선택

- 프레임워크: Next.js 15(App Router), React 19, TypeScript(strict). TypeScript는 6.0.3으로 고정한다(Next.js 15.5가 TypeScript 7을 지원하지 않는다).
- 스타일: Tailwind CSS v4. shadcn/ui는 1단계에서 쓰지 않는다(버튼 몇 개뿐이라 이득이 없다. 필요해지면 도입).
- 상태: Zustand
- 악보: VexFlow 5(SVG). 계이름 같은 글자와 구간 표시는 같은 SVG 위에 직접 얹는다.
- 소리: 직접 만든 Web Audio 엔진(`src/lib/audio/engine.ts`). Tone.js는 쓰지 않는다(필요한 기능이 음 재생뿐이라 의존성과 용량이 적은 쪽을 골랐다). 삼각파에 2배음·3배음을 더한 부드러운 음색, 저역 통과 필터, 컴프레서. 피아노 샘플은 2단계 이후 검토(용량과 로딩 때문).
- 이론 검산: 자체 이론 모듈(`src/lib/theory`). Tonal.js는 개발용 의존성으로만 두고, 테스트에서 자체 모듈의 결과를 교차 확인한다.
- 대본 형식 검사: Zod
- 테스트: Vitest(로직), Playwright(브라우저, 설치된 Chrome 사용)
- 배포: 정식 주소는 Vercel을 목표로 했으나 지금은 막혀 있다(14장). 임시로 한 파일 시범판을 Claude 링크로 전달했다.
- 한 파일 시범판: `npm run build:standalone`(esbuild와 Tailwind). 같은 컴포넌트와 수업 대본을 쓰되 주소만 `#수업id` 방식으로 바꾼 HTML 한 파일을 만든다. 바꿀 때는 `e2e/standalone.spec.ts`로 시험한다.
- 지원 브라우저: Chrome 111 이상, Safari 16.4 이상(Tailwind v4 기준). 더 오래된 교실 전자칠판 브라우저는 화면이 깨질 수 있어 실기기 확인이 필요하다.
- 글꼴: 시스템 글꼴만 쓴다(맑은 고딕, Apple SD Gothic Neo, Noto Sans KR 순). 외부 글꼴은 학교망에서 막힐 수 있다.
- 버전: 설치 시점에 호환되는 안정 버전으로 고정하고, 정확한 값은 `package.json`을 기준으로 한다.

## 5. 수업 대본 형식 v1

원칙: AI(또는 작성자)는 "무엇을 보여 줄지"만 적고, 이름·화음 종류·음 위치 같은 이론 사실은 앱이 계산한다. 계산 결과가 대본의 선언과 다르면 검산기가 막는다.

### 5.1 최상위

- `schema`: 1
- `id`: 영문 소문자와 하이픈(주소에 쓰임). 예: `c-major-triads`
- `title`, `subtitle?`
- `grade`: "공통" | "초5-6" | "중1-3"
- `key`: `{ tonic: "C", mode: "major" }` (1단계는 장조만 검산한다)
- `keyboard`: `{ from: "C4", to: "C5" }` (양 끝은 흰 건반)
- `review`: `{ author: "AI", status: "교사 검토 전" | "검토 완료", note? }`
- `elements`: 이름(영문) → 요소
- `steps`: 단계 목록 (3~16개)

### 5.2 요소

음 줄 `notes`

- `pitches`: ["C4","D4",…] 왼쪽에서 오른쪽으로 한 음씩 나란히 그린다. 임시표는 `F#4`, `Bb4`처럼 쓴다(겹임시표 없음).
- `labels?`: "없음" | "계이름" | "음이름" | "둘 다" (기본 "없음")
- `gaps?`: true면 이웃한 음 사이에 온음/반음을 표시(기본 false)
- `scale?`: "major"면 이 음들이 `key`의 장음계 한 옥타브(8음)라고 선언 → 계산으로 검산

화음 `chord`

- `pitches`: 아래에서 위로. 한 자리에 쌓아 그린다.
- `degree?`: 1 | 4 | 5. `key`의 몇째 음 위에 쌓은 화음인지 선언 → 계산으로 검산하고, 이름과 로마 숫자를 자동으로 붙인다.
- `kind?`: "triad"(기본) | "seventh". seventh는 degree 5(딸림7화음)만 허용.
- `name?`: degree가 없을 때만 쓰는 자유 이름
- `labels?`: "없음" | "이름" | "로마숫자" | "둘 다". 기본은 degree가 있으면 "둘 다".

### 5.3 단계

- `caption`: 자막(필수). 칠판 글씨처럼 짧게. 자리표시자를 채운 뒤 60자 이하.
- `show?`: 칠판에 추가할 요소 id 목록(오른쪽 끝에 붙는다)
- `hide?`: 칠판에서 뺄 요소 id 목록
- `set?`: `{ target, labels?, gaps? }` 요소의 표시 옵션을 바꾼다. 이후 단계에도 유지된다.
- `keyLabels?`: "없음" | "계이름" | "음이름" 건반 글자. 이후 단계에도 유지된다.
- `highlight?`: `{ target, notes? }` 또는 그 목록. `notes`는 1부터 센다. 생략하면 요소 전체. 이 단계에서만 적용된다. 칠판 음표와 건반이 함께 강조된다.
- `play?`: `{ target, notes?, how: "차례로" | "동시에" }` 또는 그 목록. 목록이면 앞에서부터 하나씩 재생한다.
- `ask?`: `{ type: "건반", answer, order?: "자유" | "차례로", success? }` 학생이 건반을 눌러 답한다. `answer`는 요소 id. 음 높이는 옥타브와 무관하게 음 이름(도·레·미…)이 같으면 맞는 것으로 본다.

장면 계산: 0번 단계부터 지금 단계까지 `show`, `hide`, `set`, `keyLabels`를 차례로 적용한 결과가 지금 칠판이다. `highlight`, `play`, `ask`는 지금 단계 것만 쓴다. 어느 단계로든 바로 이동할 수 있어야 한다.

### 5.4 자막 자리표시자

- 형식: `{요소.속성}` 또는 `{요소[번호].속성}` 또는 `{요소.속성:조사}`. 번호는 1부터.
- 속성: `name`(화음 이름), `numeral`(로마 숫자), `solfege`(계이름), `letters`(음이름), `count`(음 개수). `{key}`는 "다장조" 같은 조 이름.
- 여러 음이면 가운뎃점으로 잇는다. 예: "도·미·솔"
- 조사: `이/가`, `은/는`, `을/를`, `과/와`, `으로/로`, `이에요/예요`. 앞말의 마지막 글자 받침을 보고 고른다. `으로/로`는 받침 ㄹ도 "로". 앞말이 한글로 끝나지 않으면 검산 오류.
- 이름·계이름·음이름은 자막에 직접 쓰지 않고 자리표시자로 채우는 것을 원칙으로 한다. 글과 그림이 어긋나는 것을 막기 위해서다.

### 5.5 예시 (기획서의 초안을 v1 형식으로 고친 것)

```json
{
  "schema": 1,
  "id": "c-major-tonic-demo",
  "title": "다장조 으뜸화음",
  "grade": "공통",
  "key": { "tonic": "C", "mode": "major" },
  "keyboard": { "from": "C4", "to": "C5" },
  "review": { "author": "AI", "status": "교사 검토 전" },
  "elements": {
    "scale": { "type": "notes", "pitches": ["C4","D4","E4","F4","G4","A4","B4","C5"], "labels": "계이름", "scale": "major" },
    "tonic": { "type": "chord", "pitches": ["C4","E4","G4"], "degree": 1 }
  },
  "steps": [
    { "caption": "{key} 음계예요. 도에서 시작해 한 음씩 올라가요.", "show": ["scale"], "play": { "target": "scale", "how": "차례로" } },
    { "caption": "첫째, 셋째, 다섯째 음을 골라요.", "highlight": { "target": "scale", "notes": [1,3,5] }, "play": { "target": "scale", "notes": [1,3,5], "how": "차례로" } },
    { "caption": "세 음을 쌓아 함께 울리면 {tonic.name:이/가} 돼요.", "show": ["tonic"], "play": { "target": "tonic", "how": "동시에" } },
    { "caption": "건반에서 {tonic.solfege:을/를} 눌러 보세요.", "ask": { "type": "건반", "answer": "tonic" } }
  ]
}
```

## 6. 검산기 규칙

검산기는 `validateLesson(lesson)` 함수로 만들고 `{ ok, errors, warnings }`를 돌려준다. 각 항목은 `{ code, path, message }`이고 message는 한국어로 쓴다. 빌드(`npm run build`)와 테스트(`npm test`)가 모든 수업을 검사하고, 하나라도 오류면 실패한다.

오류(수업이 보이지 않아야 함)

1. 형식: 허용된 요소와 동작만 쓰였는가, 필수 값이 있는가
2. 참조: `show/hide/set/highlight/play/ask`와 자리표시자가 가리키는 요소가 있는가. 없는 것을 `hide`하거나 이미 보이는 것을 다시 `show`하지 않았는가
3. 음 표기: `C4`, `F#4`, `Bb4` 형식인가. 음역은 C4~C6(높은음자리표 오선과 덧줄 한두 줄 안)
4. 순서: 음 줄은 아래에서 위로 올라가고, 화음은 쌓은 순서가 3도씩 올라가는가
5. 음계 선언(`scale`): 계산한 장음계 한 옥타브와 음이 같은가
6. 화음 선언(`degree`, `kind`): 조의 그 자리 위에 3도씩 쌓은 화음과 음이 같은가. 1단계는 degree 1·4·5와 degree 5의 7화음만 허용
7. 이름 규칙: degree가 있으면 `name`을 직접 쓰지 못한다(앱이 계산)
8. 계이름 표시: 조 안의 음(조표로 설명되는 음)에만 가능
9. 온음/반음 표시(`gaps`): 이웃한 음 거리가 반음(1)이나 온음(2)이어야 한다
10. 건반 범위: 양 끝이 흰 건반이고, 보여 주는 모든 음과 해보기 답이 범위 안에 있다. 흰 건반 15개 이하
11. 번호: `highlight`, `play`의 음 번호가 요소의 음 개수 안에 있다
12. 해보기: `answer` 요소가 있고, `order: "차례로"`이면 음 줄 요소다
13. 자막: 비어 있지 않고, 자리표시자가 모두 풀리고, 채운 뒤 60자 이하. 조사를 붙인 값이 한글로 끝난다
14. 단계 수 3~16개. 한 단계에서 칠판에 동시에 보이는 열 수 12 이하
15. 한 단계에 한 가지만: 장면 변화(`show`+`hide`는 한 가지로 센다), `set`, `keyLabels` 중 두 가지 이상이 한 단계에 있으면 오류

경고(통과는 하되 검토)

- 음이 새로 나오는데 `play`가 없는 단계
- 자막 45자 초과
- 마지막 단계가 `ask`도 `play`도 아닌 경우

## 7. 화면 명세

### 7.1 수업 고르기 (`/`)

- 위: 앱 이름 "음악 칠판(가칭)"과 한 줄 설명
- 학교급 묶음별 구역: 공통 기초 / 초등 5~6학년 / 중학교. 수업이 없는 묶음은 "준비 중"으로 표시하지 않고 숨긴다.
- 카드: 제목, 한 줄 설명, 단계 수, 학교급 표시, "교사 검토 전 초안" 표시
- 아래: "소리가 나지 않으면 기기 볼륨과 무음 모드를 확인해 주세요." 안내
- 카드는 한 번에 누를 수 있게 크게(높이 72px 이상).

### 7.2 수업 화면 (`/lesson/[id]`)

- 한 화면에 모두 들어온다. 스크롤 없음(높이 100dvh).
- 위쪽 줄: 목록으로, 제목, 단계 "3 / 8", 테마 전환, 전체 화면(지원 기기에서만)
- 칠판 영역(남는 높이를 모두 쓴다): 위쪽 오선보, 아래쪽 건반
- 자막 영역: 큰 글씨(화면 너비에 따라 24~40px). 해보기 결과 메시지는 자막 아래 한 줄.
- 조작 줄: 이전 / 다시 듣기 / 다음 / 처음으로, 자동 재생 켜기·끄기
- 마지막 단계에서 "다음" 자리는 "처음으로"가 된다.
- 주소 `?step=3`(1부터)으로 특정 단계에서 열 수 있고, 단계를 넘기면 주소가 갱신된다(기록은 쌓지 않는다).

### 7.3 오선보

- 높은음자리표와 조표를 그린다. 1단계 수업은 모두 다장조라 조표가 없지만, 조표와 임시표가 그려져야 한다(개발용 시험 칠판으로 확인).
- 음표는 온음표(줄기 없음)로 그린다. 음 줄은 같은 간격의 열로, 화음은 한 열에 쌓아서 그린다.
- 계이름·음이름 글자는 음 아래에 같은 SVG 안에서 그린다. 글자 크기는 오선 간격에 비례한다.
- 새로 나타난 열은 0.3초 동안 서서히 나타난다(`prefers-reduced-motion`이면 생략).
- 강조 색은 음표와 글자와 건반에 같이 적용하고, 색만이 아니라 굵기나 테두리로도 구분한다.
- 열 위치는 이미 보이는 요소가 새 요소 때문에 밀리지 않게 정한다(`hide`로 앞쪽이 빠지면 왼쪽으로 당겨지는 것은 허용).
- 칠판 폭은 수업 전체에서 가장 많은 열 수를 기준으로 고정한다. 단계마다 크기가 변하지 않는다.

### 7.4 건반

- `keyboard.from`~`to`의 흰 건반과 그 사이 검은 건반을 그린다.
- 눌림, 소리 나는 중, 강조, 내가 맞힌 건반, 틀린 건반을 서로 다른 색으로 표시한다.
- 흰 건반은 너비 40px 이상으로 눌릴 수 있게(휴대폰 세로에서 흰 건반 10개 안쪽 권장). 검은 건반은 위쪽 절반을 차지하고 흰 건반보다 앞에서 눌린다.
- 건반 글자(`keyLabels`)는 흰 건반 아래쪽에 쓴다.

### 7.5 조작

- 포인터 이벤트로 마우스와 터치를 같이 처리한다. 건반은 눌림 즉시 소리가 난다(손을 뗄 때까지 기다리지 않는다).
- 다음: →, ↓, PageDown, Space, Enter. 이전: ←, ↑, PageUp, Backspace. 처음으로: Home. 다시 듣기: R. 단추에 초점이 있을 때 Space·Enter는 그 단추 동작을 우선한다.
- 단추 높이 48px 이상. 초점 표시는 항상 보인다.
- 해보기 중에도 "다음"은 막지 않는다(교사가 건너뛸 수 있다).

### 7.6 해보기

- 규칙: 음 이름이 같으면 맞다(옥타브 무관). `order: "자유"`는 순서 상관없이 모두 찾으면 완료, `"차례로"`는 순서대로 눌러야 한다.
- 메시지: 틀림 "그 음이 아니에요. 다시 눌러 보세요.", 진행 "2 / 3개 찾았어요.", 완료 "맞아요!"(또는 `success`). 완료하면 정답 음을 한 번 들려준다.
- 학생 개인정보나 기록은 어디에도 저장하지 않는다.

### 7.7 접근성과 색

- 자막 영역은 `aria-live="polite"`. 칠판 SVG에는 `role="img"`와 현재 장면을 설명하는 `aria-label`(예: "다장조 음계 8음과 으뜸화음")
- 글자와 배경 대비 4.5:1 이상(칠판과 화이트보드 두 테마 모두)
- 테마 선택은 기기에 기억한다(실패해도 동작은 계속). 이것 말고는 아무것도 저장하지 않는다.

## 8. 소리 명세

- 첫 사용자 동작(단추나 건반 누름)에서 오디오를 깨운다. 그 전에는 소리를 내지 않는다.
- 차례로: 음마다 0.5초 간격, 음 길이 0.7초. 동시에: 모든 음을 한꺼번에 시작, 길이 1.6초. 목록 재생은 항목 사이 0.9초 쉼.
- 건반 누름: 0.7초.
- 재생 중인 음은 칠판 음표와 건반이 동시에 강조된다.
- 단계를 바꾸면 재생 중인 소리와 예약된 강조를 모두 끊는다.
- "자동 재생"이 켜져 있으면 단계에 들어올 때 `play`를 재생한다(기본 켬). "다시 듣기"는 항상 재생한다.
- 주파수는 평균율 A4=440Hz로 음 이름에서 계산한다(표를 따로 두지 않는다).
- 안내: 휴대폰이 무음 모드이면 소리가 나지 않을 수 있다(특히 아이폰). 수업 고르기 화면 아래에 안내를 둔다.

## 9. 검증 수업 4편

모든 수업은 `review.author: "AI"`, `status: "교사 검토 전"`으로 시작한다. 아래는 단계 개요이고, 자막은 자리표시자를 쓰는 초안이다. 용어 확인이 필요한 곳은 [확인]으로 표시했다.

### 9.1 음이름과 계이름 (공통, 건반 C4~C5)

1. 음계 8음을 보여 주고 차례로 들려준다. 자막: 오선 위에 음이 여덟 개 있어요. 낮은 음에서 높은 음으로 올라가요.
2. 계이름을 표시한다. 자막: 노래할 때 부르는 이름이 계이름이에요. (도 레 미 파 솔 라 시 도를 차례로 강조하며 재생)
3. 음이름을 표시한다. 자막: 음마다 정해진 이름은 음이름이에요. 영어로는 C D E F G A B예요.
4. 계이름과 음이름을 함께 표시한다. 자막: 다장조에서는 도는 다, 레는 라, 미는 마… 이렇게 짝이 돼요. (자리표시자로 채움)
5. 건반 글자를 음이름으로 켜고 도 건반을 강조한다. 자막: 도(다)는 검은 건반 두 개 왼쪽의 흰 건반이에요.
6. 해보기 1: 건반 글자를 끄고 "{솔}을 눌러 보세요".
7. 해보기 2: "음이름 {마}를 눌러 보세요".

### 9.2 다장조 음계 (공통, 건반 C4~C5)

1. 음계를 계이름과 함께 보여 주고 재생. 자막: {key} 음계예요. 도에서 시작해 한 음씩 올라가요.
2. 음 사이 거리 표시를 켠다(`gaps`). 자막: 음과 음 사이의 거리는 온음과 반음 두 가지예요.
3. 미–파를 강조하고 재생. 자막: 미와 파 사이는 반음이에요. 건반에서 둘 사이에 검은 건반이 없어요.
4. 시–도를 강조하고 재생. 자막: 시와 도 사이도 반음이에요. 나머지는 모두 온음이에요.
5. 전체 재생. 자막: 온음·온음·반음·온음·온음·온음·반음. 이 모양이 장음계예요.
6. 해보기(차례로): 건반에서 도부터 차례로 눌러 보세요.

### 9.3 다장조 주요 3화음 (공통, 건반 C4~D5)

요소: 음계 `scale`, 으뜸화음 `tonic`(degree 1), 버금딸림화음 `subdom`(degree 4), 딸림화음 `dom`(degree 5)

1. 음계를 계이름과 함께 보여 주고 재생.
2. 첫째·셋째·다섯째 음을 강조. 자막: 첫째, 셋째, 다섯째 음을 골라요.
3. `tonic` 표시. 자막: 세 음을 쌓아 함께 울리면 {tonic.name:이/가} 돼요.
4. 음계의 넷째 음 강조. 자막: 넷째 음 {scale[4].solfege}에서도 같은 방법으로 쌓아 봐요.
5. `subdom` 표시. 자막: 함께 울리면 {subdom.name:이/가} 돼요.
6. 음계의 다섯째 음 강조. 자막: 다섯째 음 {scale[5].solfege}에서 시작하면요?
7. `dom` 표시. 자막: 이번에는 {dom.name:이/가} 돼요.
8. 세 화음을 강조하고 차례로 재생. 자막: 이 세 화음을 주요 3화음이라고 해요. 차례로 들어 봐요. [확인: "주요 3화음" 용어와 쓰임]
9. 해보기: {dom.name:을/를} 이루는 세 음을 건반에서 모두 눌러 보세요.

### 9.4 딸림7화음과 마침꼴 (중1-3, 건반 C4~G5)

요소: `dom`(degree 5, G4 B4 D5), `dom7`(degree 5, seventh, G4 B4 D5 F5), `tonic`(degree 1, C5 E5 G5)

1. `dom` 표시·재생. 자막: {key}의 {dom.name:이에요/예요}. {dom.solfege:을/를} 쌓았어요.
2. `dom`을 `dom7`로 바꿔 표시(`hide`+`show`), 맨 위 음 강조. 자막: 맨 위에 {dom7[4].solfege:을/를} 더 쌓으면 {dom7.name:이/가} 돼요.
3. 시와 파 강조. 자막: 시와 파가 만드는 긴장 때문에 {tonic.name:으로/로} 가고 싶어 해요. [확인: 설명 수준]
4. `tonic` 표시, `dom7`→`tonic` 순서로 재생. 자막: {tonic.name:으로/로} 가면 소리가 편안하게 풀려요.
5. 두 화음의 짝 음 강조. 자막: 시는 도로, 파는 미로 풀려요. (자리표시자로 채움)
6. 두 화음 모두 강조하고 재생. 자막: 딸림7화음에서 으뜸화음으로 끝나는 이 꼴을 마침꼴이라고 해요. [확인: "마침꼴"과 "종지" 중 교과서에서 쓰는 말]
7. 해보기: {dom7.name:을/를} 이루는 네 음을 건반에서 모두 눌러 보세요.

## 10. 용어 규칙

- 계이름: 도 레 미 파 솔 라 시(이동도). 음이름: 다 라 마 바 사 가 나(영어 C D E F G A B 병기). 조 이름: 다장조, 사장조, 바장조, 가단조 …
- 화음: 으뜸화음(Ⅰ), 버금딸림화음(Ⅳ), 딸림화음(Ⅴ), 딸림7화음(Ⅴ7). 거리: 온음, 반음.
- 확인되지 않은 용어는 자막에 쓰지 않는다. 특히 7음의 이름(이끈음/이끎음 등), 종지 종류의 이름. 쓰고 싶으면 먼저 교과서나 교사에게 확인한다.
- 학교급에 맞는 낱말을 쓴다. 초등 5~6학년이 읽을 수 있게 짧은 문장, 한자어는 필요한 만큼만.
- 예시 가락은 직접 만든 것이나 저작권이 끝난 곡만 쓴다. 교과서 수록곡은 쓰지 않는다.

## 11. 테스트 계획

자동(저장소에 포함, `npm test`, `npm run e2e`)

1. 이론 모듈: 음 해석, 음계, 화음, 한국어 이름을 15개 장조에서 Tonal.js와 교차 확인
2. 조사 처리: 받침 있는 말·없는 말·ㄹ 받침·한글 아닌 끝말
3. 자막 채우기: 정상, 번호 지정, 없는 요소, 없는 속성
4. 검산기: 4편은 통과, 일부러 망가뜨린 대본(음 하나 틀림, 화음 선언 틀림, 번호 초과, 건반 범위 밖, 한 단계에 두 가지 변화 등)은 정확한 오류로 실패
5. 장면 계산: 앞으로·뒤로·처음으로 이동해도 같은 단계는 같은 장면
6. 해보기 판정: 자유·차례로, 옥타브 무관, 틀린 건반, 중복 누름
7. 브라우저: 목록에 4편이 보임 → 각 수업을 방향키로 끝까지 → 터치 흉내로 같은 일 → 해보기 완료 → 콘솔 오류 없음 → PC·휴대폰 세로·휴대폰 가로 크기에서 화면 캡처
8. 소리: 첫 누름 뒤 오디오가 실행 상태가 되고, 재생 단계에서 음이 시작되는 횟수가 기대와 같음

사람이 해야 함(자동으로 확인할 수 없음)

- 실제 스피커로 들어 보기(음 높이, 길이, 시끄럽지 않은지)
- 아이폰·안드로이드 실기기에서 소리와 터치
- 교실 전자칠판·TV·프로젝터에서 글씨 크기와 소리 지연
- 교사의 수업 내용과 용어 검토

## 12. 개발 순서와 규칙

순서: 스캐폴드 → 이론 모듈 → 대본 형식과 검산기 → 자막 채우기와 장면 계산 → 수업 4편 → 칠판(오선보, 건반) → 소리 → 수업 화면과 조작 → 수업 고르기 → 브라우저 시험 → 배포

규칙

- 작은 단위로 커밋한다. 메시지는 한국어로 "무엇을 왜".
- 코드 주석은 한국어로, "왜"가 비자명한 곳에만 쓴다.
- 실행 중 외부 요청 금지(글꼴, CDN, 분석). 소리와 악보 글꼴은 모두 앱에 포함한다.
- 칠판 화면에서만 VexFlow를 불러온다. 수업 고르기 화면은 가볍게 유지한다.
- 새 수업을 추가할 때는 대본 파일만 추가하고, 검산기를 통과해야 목록에 나온다.
- 이론 사실(음 이름, 화음 구성)을 코드나 대본에 손으로 적어 두지 않는다. 이론 모듈이 계산한다.
- 이 문서와 기획서가 바뀌는 결정이 생기면 문서를 먼저 고친다.
