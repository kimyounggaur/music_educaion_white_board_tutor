- 작성일: 2026-11-17

- 이 문서의 역할: 이 프로젝트의 기준 문서. 결정이 바뀌면 이 문서를 먼저 고친다.
- 변경 이력
  - v0.3 (2026-11-17): 개발 진행 방식 확정(A), 1단계 시범판 구현 결과와 배포 상태 반영, 기술 구성 변경(소리 엔진), 정해야 할 것 갱신
  - v0.2 (2026-11-17): 대상 학년 확정(초등 5학년~중학교 3학년), 교육과정 음악 요소 표 대조 완료, 1단계 범위 구체화
  - v0.1 (2026-11-17): 첫 작성

## 1. 한 줄 정의

교사가 교실 화면에 띄워 쓰는 음악 수업용 칠판. 질문 하나를 오선보와 건반 위에 한 단계씩 판서하며 설명하고, 판서된 음은 그대로 소리가 난다.

## 2. 확정된 결정 (2026-11-17)

1. 주 사용자는 교사다. 교실의 전자칠판이나 TV에 띄워 수업에 쓴다. 학생은 계정 없이 화면을 함께 보고, 필요하면 나와서 화면을 누른다.
   - 이유: 교사가 AI 오류를 걸러 주고, 학생 개인정보를 다루지 않아 첫 버전이 가볍다.
2. 수업 방식은 혼합형이다. 미리 만들어 검토한 "검증 수업"이 기본이고, AI가 즉석에서 만드는 "자유 질문"을 덧붙인다.
   - 이유: 자유 질문만 두면 질문마다 AI 비용과 대기 시간이 들고 정확도 편차가 커진다.
3. Harmony와 별도 앱으로 시작한다. 악보 표시와 소리 재생 도구는 Harmony와 같은 것을 쓴다.
   - 이유: 실험 속도가 빠르고, 나중에 합치기 쉽다.
4. 대상 학년은 초등 5학년부터 중학교 3학년까지다.
   - 영향: 사용자가 두 부류다(초등 교사, 중학교 음악 교사). 수업은 공통 기초, 초등 5~6학년 확장, 중학교 확장의 세 묶음이 된다.
   - 만드는 순서: 공통 기초부터. 두 학교급이 함께 쓰는 내용이라 가장 효율적이다.
5. 1단계 개발 진행 방식은 A다. 이 프로젝트 대화에서 Claude가 개발하고 링크로 전달하며, 코드는 GitHub에 올려 이후 맥북의 Claude Code에서 이어 갈 수 있게 한다.
   - 근거: 13장의 추천안이었고, 사용자가 선택했다(2026-11-17).

## 3. 참고 데모와 차별점

참고 데모: Claude 공식 X 계정이 2026-11-10에 올린 Fable 5.2 초기 실험 스레드 중 Tyler Nishida의 칠판 데모. 질문을 넣고 버튼을 누르면 답이 칠판에 한 단계씩 그려지고, 넘기는 속도는 학습자가 정한다. 영상 자체는 직접 확인하지 못했고 2차 자료로 파악했다. 음성 해설과 후속 질문 기능이 있는지는 미확인.

음악용으로 달라지는 점

- 들리는 판서: 칠판의 음표와 화음을 누르면 바로 소리가 난다.
- 음악으로 답하기: 글 대신 건반(이후 리듬) 터치로 답하고 바로 확인한다.
- 검증되는 판서: AI는 그림을 그리지 않고 "수업 대본"만 쓴다. 악보와 소리는 앱이 대본대로 만들고, 이론 오류는 앱이 계산으로 검산한다.

기준 예시: 2026-11-17 대화에서 만든 "으뜸화음" 스케치. 다장조 음계 → 도·미·솔 고르기 → 화음으로 쌓기 → 건반으로 해보기의 4단계.

## 4. 사용 장면

수업 전 (준비 모드, 교사 PC나 휴대폰)

1. 주제 목록에서 검증 수업을 고르거나, 질문을 입력해 수업을 미리 만든다.
2. 미리보기로 단계를 넘겨 보며 확인한다.
3. 수업 링크를 저장해 둔다.

수업 중 (수업 모드, 전자칠판이나 TV)

1. 링크를 열면 큰 화면용 칠판이 뜬다.
2. "다음"으로 한 단계씩 판서하고, 설명은 교사가 자기 말로 한다. 필요할 때 "듣기"를 누른다.
3. "해보기" 단계에서 학생이 나와 건반을 누른다. 터치가 안 되는 화면이면 교사가 마우스로 누른다.
4. 학생 질문이 나오면 자유 질문을 입력한다. 비슷한 검증 수업이 있으면 그것을 먼저 권한다.

## 5. 설계 원칙

1. 교사가 주인공이다. 자막은 칠판 글씨처럼 짧게 쓰고, 1차에는 음성 해설을 넣지 않는다.
2. 한 단계에 한 가지만 바뀐다.
3. 보이는 것과 들리는 것은 같은 데이터에서 나온다.
4. 터치와 마우스를 모두 지원한다. 전자칠판이 없는 교실이 아직 많다(9장).
5. 화면은 가로 16:9. 위쪽은 칠판(오선보와 건반), 아래쪽은 자막과 조작 버튼. 큰 전자칠판은 위쪽에 손이 닿지 않기 때문이다.
6. 학생 개인정보는 받지 않는다.
7. AI가 만든 수업은 그렇게 표시하고, 검산을 통과한 것만 보여 준다.
8. 수업마다 학교급(공통, 초등 5~6학년, 중학교)을 표시하고, 자막의 낱말과 깊이를 그에 맞춘다.

## 6. 기능 범위

1차 (프로토타입에서 첫 공개까지)

- 칠판 요소: 오선보(높은음자리표, 음표, 조표와 임시표, 계이름·음이름 표시), 건반, 짧은 자막, 동그라미와 색 강조
- 소리: 피아노 음색, 단계별 듣기, 건반 터치 소리, 소리 나는 음표와 건반 동시 강조
- 진행: 이전·다음·처음부터, 단계 표시, 키보드 방향키와 프레젠터(발표용 리모컨) 지원
- 해보기: 건반 터치로 답하고 정답 확인
- 검증 수업: 4편으로 시작해 학교급별 10편 안팎까지
- 자유 질문: AI 대본 생성, 자동 검산, "AI가 만든 수업" 표시
- 수업 링크 저장과 공유
- 판서 효과: 요소가 차례로 나타나는 방식. 손글씨처럼 그려지는 효과는 이후

이후 후보

- 리듬 요소(박, 박자, 리듬꼴, 메트로놈, 리듬 터치)
- 국악 요소(장단, 토리, 율명)
- 낮은음자리표, 음정 표시
- 리코더·단소 운지, 기타 코드
- 교사 펜 판서(화면 위에 덧쓰기), 휴대폰 리모컨, 음성 질문
- 학생 기기 참여와 퀴즈. 이때는 학생 개인정보 설계가 먼저 필요
- 음성 해설
- Harmony 연동(악보의 한 구절을 가져와 설명)

## 7. 동작 구조

쉬운 설명

1. 수업 대본: 수업 한 편을 "단계별 자막 + 그릴 음표 목록 + 들려줄 소리 + 해보기 문제"로 적은 문서. 검증 수업은 저장해 둔 대본이고, 자유 질문은 AI가 이 형식으로 새로 쓴다.
2. 검산: 앱이 대본을 받아 형식과 음악 이론을 계산으로 확인한다.
3. 칠판: 통과한 대본을 앱이 악보·건반·소리로 바꿔 한 단계씩 보여 준다.

AI가 그림을 직접 그리지 않으므로 악보 모양이 깨지거나 그림과 소리가 어긋나는 일이 구조적으로 생기지 않는다.

개발용 메모 (개발 세션에서 참고)

- 기술 구성(1단계 구현 기준): Harmony와 같은 계열인 Next.js, TypeScript, Tailwind, Zustand, VexFlow(악보)를 쓰고, 소리는 Tone.js 대신 직접 만든 Web Audio 엔진을 썼다. shadcn/ui는 1단계에서 쓰지 않았다. 정확한 버전은 개발 지시서 3장과 `package.json`을 따른다.
- 1단계에는 대본을 앱 안의 파일로 둔다. 데이터베이스(Supabase)는 수업 저장이 필요해지는 2단계부터 쓴다.
- OSMD는 악보 파일 전체를 표시하는 도구라 이 앱에는 쓰지 않는다.
- 이론 계산은 자체 모듈로 만들었고, Tonal.js는 개발용 시험에서 결과를 교차 확인하는 데만 쓴다.
- 대본 형식 초안(확정본은 개발 지시서 5장의 v1). `grade` 값은 "공통", "초5-6", "중1-3" 중 하나.

```json
{
  "title": "다장조 으뜸화음",
  "grade": "공통",
  "key": "C장조",
  "elements": {
    "scale": { "type": "notes", "pitches": ["C4","D4","E4","F4","G4","A4","B4","C5"], "labels": "계이름" },
    "tonic": { "type": "chord", "pitches": ["C4","E4","G4"], "name": "으뜸화음" }
  },
  "steps": [
    { "caption": "다장조 음계예요. 도에서 시작해 한 음씩 올라가요.", "show": ["scale"], "play": { "target": "scale", "how": "차례로" } },
    { "caption": "첫째, 셋째, 다섯째 음을 골라요.", "highlight": { "target": "scale", "notes": [1, 3, 5] }, "play": { "target": "scale", "notes": [1, 3, 5], "how": "차례로" } },
    { "caption": "세 음을 쌓아 함께 울리면 {tonic.name}이 돼요.", "show": ["tonic"], "play": { "target": "tonic", "how": "동시에" } },
    { "caption": "건반에서 {tonic.pitches}를 눌러 보세요.", "ask": { "type": "건반", "answer": "tonic" } }
  ]
}
```

- 자막 속 음 이름과 화음 이름은 AI가 직접 쓰지 않고 데이터에서 채운다(예: `{tonic.name}`). 글과 그림이 어긋나는 것을 막기 위해서다. 값을 채울 때 조사(이/가, 을/를) 처리가 필요하다.
- 검산 규칙: (1) 정해진 요소와 동작만 썼는가 (2) 음들로 계산한 음계·화음·음정 이름이 대본과 같은가 (3) 마디마다 음 길이 합이 박자표와 맞는가 (4) 음역, 단계 수, 자막 길이가 범위 안인가.
- 검산 불통과 시 한 번 다시 생성하고, 또 실패하면 비슷한 검증 수업을 권한다.
- 비슷한 구조의 공개 구현 사례가 있다(AI가 "말할 문장 + 칠판 동작"으로 수업을 계획). 코드는 검토하지 않았다. 14장 링크 참고.

## 8. 수업 콘텐츠 계획

교육과정 근거

2022 개정 음악과 교육과정의 음악 요소 표를 기준으로 한다. 공식 문서 사본의 추출본 두 가지와 중학교 교사용 지도서를 대조해 정리했다.

- 초등 5~6학년: 박과 박자, 여러 가지 리듬꼴, 음이름·계이름·율명, 장음계·단음계, 주요 3화음, 다양한 소리의 어울림, 여러 지역의 토리, 형식(긴자진 형식, 시조 형식, aba, AB 등), 셈여림의 변화, 빠르기의 변화, 관악기·현악기의 음색 등
- 중학교 1~3학년: 여러 가지 박자와 그 리듬꼴, 여러 가지 음계, 딸림7화음, 종지, 다양한 소리의 어울림, 여러 지역의 토리, 형식(연음 형식, 한배에 따른 형식, 론도, ABA, 변주곡 등), 셈여림의 변화, 빠르기의 변화, 여러 가지 음색 등
- 적용 시기: 2022 개정 교육과정은 2026년에 초등 5~6학년과 중학교 2학년까지 넓어졌고, 중학교 3학년은 2027년부터다.
- 공통 기초의 근거: 중학교 교사용 지도서(미래엔 음악①, 개정 연도 미확인)에도 다장조의 계이름과 음이름, 조별 음계와 주요 3화음이 다시 나온다.
- 남은 확인: 교과서마다 단원 배치가 다르므로 수업 목록은 교과서와 교사 검토로 확정한다.

수업 묶음

- 공통 기초(두 학교급 모두 사용): 음이름과 계이름, 다장조 음계, 다장조 주요 3화음
- 초등 5~6학년 확장 후보: 가단조 음계, 사장조·바장조 음계와 주요 3화음, 박과 박자, 여러 가지 리듬꼴, 셈여림과 빠르기의 변화
- 중학교 확장 후보: 딸림7화음과 마침꼴(종지), 여러 가지 음계(단음계 세 가지 등), 조표가 있는 조의 음계와 화음, 여러 가지 박자와 리듬꼴, 형식(론도, ABA, 변주곡)
- 국악(두 학교급 공통, 이후): 장단, 여러 지역의 토리, 율명

1단계 수업 4편 (모두 음높이 계열이라 오선보와 건반만으로 만들 수 있다)

1. 음이름과 계이름 (공통)
2. 다장조 음계 (공통)
3. 다장조 주요 3화음: 으뜸화음, 버금딸림화음, 딸림화음 (공통)
4. 딸림7화음과 마침꼴 (중학교)

검증 수업을 만드는 절차: AI로 초안 작성 → 자동 검산 → 사람 검토(가능하면 해당 학교급의 현직 교사) → 저장.

## 9. 학교 현장 조건 (2026-11 조사)

전자칠판 보급

- 2025년 10월 보도 기준 전국 평균 보급률은 39%이고 지역 차가 크다. 세종 100%, 대전 74%, 부산 52%, 서울 47%, 인천 25%.
- 경기는 2024년 기준 설치율 5.4%로 보도됐다.
- 경남은 2026년 10월 기준 66.2%이고, 2027년 2월까지 전 교실 보급을 계획했다.
- 시사점: 전자칠판은 늘고 있지만 아직 없는 교실이 많다. TV나 프로젝터에 PC를 연결한 환경에서도 똑같이 쓸 수 있어야 한다.

학교 도입 절차

- 교육부가 2025년 12월 말 "학습지원 소프트웨어 선정 기준"을 발표했고, 2026학년도 1학기부터 적용한다.
- 대상: 학생 개인정보를 처리하는 소프트웨어, 또는 교과 성취기준과 관련된 학습 콘텐츠를 담고 학교 교육과정 운영 지원을 목적으로 만든 소프트웨어. 둘 중 하나만 해당해도 대상이다.
- 제외: 교사가 수업 준비나 행정 업무에 학생 개인정보 처리 없이 쓰는 소프트웨어.
- 절차: 교원 의견 수렴 → 기준 충족 확인 → 학교운영위원회 심의 → 학교장 확정.
- 필수기준은 모두 개인정보 보호 항목이다. 교육부는 업체가 준수 여부를 확인해 학교에 제공하고 에듀집(edzip.kr) 게시판에 올리도록 안내할 계획이라고 밝혔다.
- 시사점: 이 앱은 교과 내용을 담으므로 학교가 정식 교육자료로 선정하려면 심의 대상이 될 가능성이 높다. 학생 개인정보를 받지 않으면 필수기준 대응은 단순해진다. 정확한 적용 여부는 가이드라인 원문으로 확인이 필요하다(법률 자문 아님).

## 10. 유사 서비스와 자리 잡기

- 고둥둥심포니 for EDU(와이즈온미디어): 캐릭터로 음악 이론을 풀고 초등 음악 교과와 연계한 작곡 활동을 제공하는 학생 참여형 플랫폼. 음악 비전공 교사도 쓰기 쉽게 기획했다고 밝혔다.
- Flat for Education: 클라우드 악보 작성 도구. 음악 이론 연습 문제 생성과 자동 채점을 제공한다.
- 교과서 출판사의 교수 지원 자료도 있다. 이번 조사에서 개별 확인은 하지 않았다.
- 우리 자리: 정해진 콘텐츠를 재생하는 것이 아니라, 질문에 맞춰 그 자리에서 단계별 판서를 만들어 주는 "설명 도구". 판서된 음이 바로 소리 나고, 이론은 앱이 검산한다.

## 11. 단계별 계획

- 0단계 구상(완료): 이 기획서.
- 1단계 핵심 엔진 프로토타입(범위 확정안)
  - 포함: 수업 고르기 화면, 칠판 화면(오선보·건반·자막·강조), 소리(듣기, 건반 터치), 진행(이전·다음·처음부터, 방향키와 프레젠터), 해보기(건반으로 답하기), 대본 형식 v1과 검산기, 검증 수업 4편, 큰 화면과 휴대폰 화면 대응, 링크로 접속
  - 제외: AI 자유 질문, 로그인, 수업 저장, 리듬 요소, 국악, 펜 판서. AI를 부르지 않으므로 AI 사용료가 들지 않는다.
  - 완료 기준: (1) 4편 모두 끝까지 진행되고 검산기를 통과한다 (2) PC와 휴대폰 브라우저에서 소리·터치·방향키가 정상이다 (3) 실제 교실 화면에서 한 번 이상 시연한다 (4) 초등 교사와 중학교 음악 교사를 포함해 3명 이상에게 보여 주고 의견을 받는다
  - 진행 상황(2026-11-17): 구현과 자동 시험을 마쳤다. 수업 4편, 칠판, 소리, 해보기, 검산기, 큰 화면·휴대폰 화면, 두 가지 색 테마가 동작한다. 완료 기준 (1)은 충족했고, (2)는 자동 시험(PC·TV·휴대폰 세로·휴대폰 가로 크기의 Chrome)까지 확인했다. 실제 휴대폰·교실 기기 확인과 (3), (4)가 남았다.
  - 전달: Claude 링크(비공개 시범판)로 휴대폰에서 열 수 있다. 정식 주소는 Vercel 팀의 이용 제한 때문에 보류 중이다(개발 지시서 14장).
- 2단계 자유 질문: AI 대본 생성, 자동 검산, 준비 모드, 링크 저장.
- 3단계 콘텐츠 확장: 검증 수업을 학교급별 10편 안팎으로, 리듬 요소, 해보기 유형 추가.
- 4단계 학교 도입 준비: 선정 기준 대응 자료, 개인정보 처리방침, 교사 계정과 요금 검토.

검증할 가설

1. 음악 비전공 초등 담임교사는 이론 설명에 부담이 있고, 정확한 판서와 소리를 대신해 주는 도구를 원한다. 선행 연구에 담임교사 음악 수업 전문성 지원의 필요성이 언급되지만, 직접 확인이 필요하다.
2. 중학교 음악 교사는 전공자라 설명 대행보다 수업 자료 준비 시간 절감과 시청각 효과를 기대한다. 초등 교사와 기대가 다를 수 있다.
3. 교사는 즉석 생성보다 검증 수업을 더 신뢰한다.
4. 교실 기기에서 터치와 소리가 문제없이 동작한다.

## 12. 위험과 대응

- 대상 범위 확대(두 학교급) → 검증 수업 수와 검토 부담 증가. 공통 기초부터 만들고, 학교급별 검토자를 따로 확보한다
- AI 대본의 이론 오류 → 자동 검산, 검증 수업 우선, 교사 미리보기, 오류 신고 버튼
- 수업 중 대기 시간 → 준비 모드에서 미리 생성, 수업 중에는 검증 수업 우선 추천
- 교실 기기 편차(전자칠판 내장 브라우저, 소리 지연, 학교망 차단) → 1단계에서 실제 교실 기기로 시험, 교실 PC 브라우저를 우선 지원
- 학교 도입 절차 → 학생 개인정보 미수집 유지, 4단계에서 대응 자료 준비
- AI 비용 → 검증 수업은 저장된 대본 재생이라 추가 비용 없음. 자유 질문은 횟수 제한과 같은 질문 재사용
- 수업 중 부적절한 생성물 → 음악 주제로 제한, 준비 모드 사용 권장
- 저작권 → 예시 가락은 직접 만든 것이나 저작권이 끝난 곡만 사용. 교과서 수록곡의 악보와 음원은 쓰지 않는다(확인 필요, 법률 자문 아님)
